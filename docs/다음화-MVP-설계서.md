# 다음화 MVP 설계서 (초안)

작성일: 2026-10-15 / 상태: 대략적인 초안, 검증 전

## 1. 한 줄 설명

설정과 떡밥을 기억해 주고, 그 기억을 바탕으로 연재 방향 조언, 초안, 교정까지 이어 주는 웹소설 연재 파트너.

## 2. 대상과 문제

- **대상:** 장기 연재하는 웹소설 작가 (웹툰은 보류)
- **문제:** 연재가 길어지면 작가가 풀어 놓은 떡밥, 세계관, 인물 특성을 기억하지 못해 오기(설정 오류)가 생긴다.
- **핵심 약속:** 모든 단계가 위키를 근거로 움직이고, 오기를 지적할 때 원고 문장과 위키 항목을 함께 보여 줘서 작가가 바로 검증할 수 있다.

## 3. 원칙

1. 작가가 승인한 것만 위키(정본)에 반영한다. AI는 제안만 한다.
2. AI가 추측한 설정은 [가정]으로 표시하고 정본과 구분한다.
3. 모든 사실에 출처 회차를 붙인다.
4. 질문은 한 번에 하나, 언제든 건너뛸 수 있다.
5. 기획 때는 질문형, 집필 중에는 빠른 점검만 한다. 질문 피로를 줄인다.
6. 변경은 덮어쓰지 않고 이력으로 쌓는다.

## 4. MVP 기능 (17개, 전부 구현이 목표)

| # | 기능 | 설명 |
|---|---|---|
| 1 | 질문형 인터뷰 | 질문 하나씩, 건너뛰기 가능, 답은 후보 사실로 정리해 작가 승인 후 반영 |
| 2 | 설정 위키 | 인물 카드, 세계관 규칙, 장소, 표기 통일, 회차별 요약 |
| 3 | 사실 태그 | 확정/가정/미정과 출처 회차 |
| 4 | 떡밥 장부 | 심음/발전/회수/폐기. 회수는 심은 회차 이후만 인정 |
| 5 | 변경 이력, 되돌리기, 내보내기 | 이력 표에 쌓기, 백업 파일(markdown/JSON) |
| 6 | 기존 원고 가져오기 | 연재 중인 원고를 읽어 위키 초안 자동 생성 |
| 7 | 근거 붙은 오기 점검 | 원고 문장과 위키 항목을 함께 제시, AI는 제안만 |
| 8 | 주기 점검 | 목표 회차가 지난 열린 떡밥, 오래 안 나온 인물 |
| 9 | 필요한 카드만 불러오기 | 이번 회차 관련 카드와 열린 떡밥만 AI에 전달 (비용, 정확도) |
| 10 | 관계 그래프 | 인물, 장소, 사건 관계. 회차 필터로 타임라인 역할 (제안안) |
| 11 | 독자 시뮬레이션 | 가상 독자 페르소나가 읽고 이탈, 혼란 구간 지적 |
| 12 | 연재 방향 조언 | 열린 떡밥과 인물 상태 기반 다음 전개 제안 |
| 13 | 초안 작성 | 인물별 문체 카드 기반 |
| 14 | 맞춤법, 어색한 표현 수정 | 기존 맞춤법 도구 연결 (도구는 미정) |
| 15 | 연재 일정 관리 | 마감, 비축분, 휴재 계획 |
| 16 | 팀 모드 | 위키 공유, 권한 구분, 편집자 코멘트 (선택 기능) |
| 17 | 작품 보관함과 이어쓰기 | 원고 저장과 회차 관리, 작품 목록 대시보드, 중단한 작업 재개, 승인 대기 목록 보관 |

### 폐지/보류

- 폐지: 독자용 공개 위키
- 보류: 웹툰 모드(인물 카드 이미지 포함), 소설을 웹툰 콘티로, 번역/해외 연재
- 보류: 창작 기여 리포트, 프라이버시 모드, 작가가 직접 고친 기록 보관

## 5. 기술 방향

- **형태:** 웹 (Next.js). 설치 없이 링크로 사용
- **계정제:** 필수. 1인 사용자가 기본이고 팀 모드는 선택 기능
- **저장:** PostgreSQL을 기준 저장소로. 자유 필드(인물 카드 항목)는 JSONB, 원고와 카드 서술은 텍스트(markdown). 내보내기용으로 markdown/JSON 생성
- **AI 호출:** 서버를 거침 (키 보호). 비용은 필요한 카드만 보내는 설계(기능 9)로 절감. BYOK는 선택 옵션 후보
- **클라이언트 처리(서버 부하 절감):** 원고 파일 파싱과 회차 분할, 카드 검색과 인덱싱, 관계 그래프 렌더링, 변경 비교(diff), 자동 저장 캐시, 백업 파일 생성, 일정 계산. Web Worker와 IndexedDB 활용
- **서버 전담:** 인증과 권한, 사용량 제한, 위키 저장과 동기화, AI 호출
- **긴 작업:** 원고 가져오기는 진행 상태를 서버에 저장해 이어서 할 수 있게 하고, 백그라운드 작업으로 처리

## 6. 데이터 모델 (초안)

- `users`: 계정
- `works`: 작품
- `chapters`: 회차 본문, 순서, 상태(초안/완료)
- `chapter_versions`: 회차 수정 이력
- `characters`: 인물 카드 (고정 필드 + JSONB 자유 필드)
- `world_entries`: 세계관, 장소, 규칙
- `facts`: 사실 한 건 (내용, 상태: 확정/가정/미정, 출처 회차, 근거 문장)
- `threads`: 떡밥 (내용, 심은 회차, 회수 목표, 상태, 관련 인물)
- `thread_events`: 떡밥의 심음/발전/회수 기록
- `relations`: 관계 그래프의 연결 (대상 둘, 종류, 유효 회차 범위)
- `style_cards`: 인물별/작품 문체 카드
- `issues`: AI가 제안한 오기 지적 (원고 문장, 위키 항목, 판정 상태)
- `interview_sessions`, `ai_messages`: 인터뷰 진행 상태와 대화 기록
- `import_jobs`: 원고 가져오기 진행 상태
- `schedule_items`: 마감, 비축분, 휴재
- `members`: 팀 모드 구성원과 권한
- `change_log`: 모든 위키 변경 이력 (제안자: AI/작가, 승인 여부)

## 7. 핵심 흐름

1. **설정 입력:** 질문 → 답을 후보 사실로 정리 → 작가가 태그(확정/가정/미정) 선택 → 위키 반영 + 이력 기록
2. **집필 전:** 이번 회차 등장 인물 카드, 열린 떡밥, 직전 회차 요약만 불러오기
3. **집필 후:** 새 회차에서 사실 추출 → 위키와 충돌 확인 → 제안을 issues에 저장 → 작가가 판정 후 반영
4. **정기 점검:** 지연된 떡밥, 장기 미등장 인물 목록 표시
5. **재방문:** 로그인 → 대시보드 → 마지막 작업 지점, 승인 대기 건, 열린 떡밥 요약 → "다음 화 쓰기"

## 8. 화면 목록

- 로그인, 작품 목록 대시보드
- 작품 시작 (인터뷰, 원고 가져오기 선택)
- 설정 보드 (인물, 세계관, 떡밥 장부, 관계 그래프)
- 집필 화면 (원고 + 관련 카드 패널 + 점검 버튼 + 승인 모달)
- 승인 대기/이력 화면
- 연재 일정, 연재 방향 조언, 독자 시뮬레이션 결과
- 팀 설정 (선택)

## 9. 구현 순서 (제안)

1. **세로 줄기:** 로그인, 작품 생성, 원고 저장(17), 설정 위키(2, 3), 오기 점검(7), 이력(5)
2. 떡밥 장부(4), 선택적 로드(9), 인터뷰(1), 주기 점검(8)
3. 기존 원고 가져오기(6), 관계 그래프(10)
4. 연재 방향 조언(12), 초안 작성(13, 문체 카드 먼저), 맞춤법(14)
5. 독자 시뮬레이션(11), 일정 관리(15)
6. 팀 모드(16)

## 10. 리스크

- **경쟁 중복:** 설정 관리, 초안, 첨삭, 맞춤법을 한 서비스에서 제공하는 웹 서비스가 이미 있다. 차별점은 "모든 단계가 위키를 근거로 하고, 오기 지적에 근거 문장을 붙인다"는 약속이다.
- **범위:** 17개 전부는 1인 개발에 크다. 1번 줄기를 먼저 검증한다.
- **유지비:** 작가가 승인을 계속해야 위키가 최신으로 유지된다. 승인 피로를 줄이는 UX가 필요하다.
- **문체 평준화:** AI 초안이 인물 목소리를 비슷하게 만들 수 있다. 문체 카드로 대응한다.
- **AI 비용:** 호출량이 비용의 대부분. 선택적 로드와 사용량 제한이 필수.
- **개인정보와 저작권:** 원고를 외부 AI에 보내는 것에 대한 약관과 동의 문구가 필요하다.

## 11. 검증 계획

1. 웹소설 작가 5~10명 인터뷰: 설정 오기가 얼마나 자주 나는지, 어떤 식으로 나는지, 돈을 낼 의향
2. 3개 화면(작품 시작, 설정 보드, 집필) 클릭 목업으로 사용 테스트
3. 웹소설 10화 분량으로 오기 점검 정확도 테스트

## 12. 미확인/열린 항목

- 서비스 이름 "다음화"의 중복 여부 (검색 안 함)
- 호스팅, DB, 인증 서비스 선택과 가격, 실행 시간 한도
- 맞춤법 검사 도구 선택
- AI 모델 선택과 한국어 품질, 호출 단가
- BYOK를 선택 옵션으로 둘지
- "1인"의 의미 (1인 사용자 기본으로 이해함. 1인 개발 의미도 포함한 구조로 설계)
- 요금제와 수익 모델
- 관계 그래프의 회차 필터를 타임라인 대용으로 쓰는 안은 제안일 뿐 검증 전
