## 4. 발견

### 4.1 서버 측

- 서버 다운, 5xx 응답, 서버 오류 로그 모두 없었다. 최종 `next start` 로그 (`.data/stress/server.log`, 삭제 전 확인)에는 시작 메시지 5줄뿐이었다. `next dev` 로그 149줄에도 error, warn, `⨯`가 없었다.
- Server Action 줄 막힘은 재현되지 않았다. 편집 자동 저장은 인터뷰 턴과 같은 시간대에 실행되었고 "저장됨"이 모두 나왔다. 인터뷰 질문과 답은 route handler(`fetch`)로 호출되므로 Server Action 큐와 무관하다. 인터뷰 끝내기와 건너뛰기는 Server Action이고 이 역시 막히지 않았다.
- 회차 점검도 Server Action이 아닌 route handler다. 점검 중에도 인터뷰와 편집이 막히지 않았다.
- 취소는 설계대로 동작했다. 취소 요청이 서버에 전달되어 AI 호출이 3초 안에 중단되고 `ai_runs`에 `error`로 기록되었다. 점검 탭이 응답 전에 닫혔을 때도 점검의 AI 호출 두 건이 같은 방식으로 중단되었다(§4.2 참고). 이는 의도된 동작으로 보인다.

### 4.2 스크립트 측 (수정함, 커밋에 포함)

- 기본 Playwright 동작 타임아웃이 무제한이라 멈춘 클릭을 감지하기 어려웠다. 컨텍스트 기본 타임아웃을 60초로 두었다.
- "인터뷰를 끝냈습니다." 텍스트 매칭이 중복되었다. 완료 패널의 다른 문장으로 바꿨다.
- 회차 점검 확인을 패널 영역 대신 POST 응답으로 바꿨다.
- 실패 시 페이지 텍스트와 스크린샷을 남긴다.

### 4.3 기타 관찰

- 취소로 끊긴 요청 외에 `net::ERR_ABORTED`가 많았다. `next start` 실행에서 392건, `next dev`에서 8건이다. 대부분 Next.js 클라이언트 내비게이션 중 `?_rsc=` 요청이거나 스크립트가 페이지를 옮기면서 끊긴 요청이었다. 서버 오류는 아니며 사용자 화면 오류도 없었다(추정).
- `next dev`의 서버 프로세스 RSS는 `next start`보다 대략 1GB 이상 컸다. 원인은 확인하지 않았다. 이 실행만으로 누수로 판단하지 않는다.
