# AI가 참고한 설정 보기, 한국어 문구 정리 설계 (2026-11-04)

## 왜

2026-11-04 무료 플랜으로 StoryBench를 직접 써 보니, 에디터에 "AI가 기억하는 것" 패널이 있어 AI에 넘기는 기억을 보여 준다. 다음화는 "근거를 인용하는 점검"과 "작가가 승인한 설정만 쓴다"를 내세운다. 그렇다면 점검이 실제로 어떤 설정을 AI에 넘겼는지도 보여 줘야 한다.

지금 집필 화면의 `관련 카드` 탭은 원고에 이름이 나온 카드만 보여 준다. 점검이 AI에 보내는 묶음(컨텍스트 팩)과는 다르다.

- 사실은 이번 화에 유효한 것만 간다.
- 열린 떡밥, 카드 사이 관계, 앞 두 화 요약, 이름 규칙이 같이 간다.
- 분량 한도(16,000자)를 넘으면 순위가 낮은 항목이 빠진다.

같은 조사에서 StoryBench 화면에 영어("Unresolved", "EP.4")가 섞여 있었다. 우리도 영어가 새지 않게 지킨다. 지금 찾은 곳은 대화상자와 시트의 X 버튼 화면 낭독 문구 `Close`, 그리고 대화상자 아래 닫기 버튼의 `Close` 다. 앱 밖 주소의 404 페이지도 Next 기본 영어 화면일 수 있다.

## 할 일

1. **점검과 같은 팩을 만드는 함수 하나 (서버)**
   - `runChapterCheck` 안의 팩 만들기(`keepNamed: true`, `CONTINUITY_BUDGET_CHARS`)를 함수 하나로 뺀다.
   - 점검과 보기가 같은 함수를 쓰므로 둘이 어긋나지 않는다.
2. **보기용 읽기 (서버)**
   - 회차 하나의 저장된 원고로 그 팩을 만들어 화면에 쓸 모양으로 돌려준다. AI는 부르지 않는다.
   - 작품 구성원이면 누구나 볼 수 있다(독자 역할 포함). 구성원이 아니면 늘 `NOT_FOUND` 다.
3. **점검 탭의 `AI가 참고한 설정` 칸 (화면)**
   - 기본은 접혀 있다. `AI가 참고한 설정 보기` 를 누르면 펼치고 불러온다.
   - 펼쳐 둔 채 점검이 끝나면(수동이든 자동이든) 다시 불러온다.
   - 보여 주는 것:
     - 안내: `회차 점검은 저장된 원고에 나온 카드와 항상 넣기로 정한 카드, {N}화에 유효한 사실, 열린 떡밥, 앞 회차 요약만 AI에 보냅니다.`
     - 설정 카드: 이름, 종류, 요약, 카드 열기 링크. 사실마다 내용, `확정`/`가정`/`미정`, 유효 회차.
     - 보관한 회차에서는 이 칸을 보이지 않는다.
     - 분량 한도로 빠진 카드 이름
     - 열린 떡밥: 제목, 상태, 회수 목표, `회수 목표 지남`
     - 앞 회차 요약: 회차 이름
     - 관계와 이름 규칙 수
4. **영어 문구 정리**
   - X 버튼과 닫기 버튼의 `Close` 를 `닫기` 로 바꾼다.
   - 앱 전체 404 페이지를 한국어로 만든다.
   - e2e 하나가 주요 화면의 보이는 글자와 `aria-label` 에서 영어 낱말을 찾아, 있으면 실패한다.
     - 허용 목록은 파일 형식과 고유 이름만 둔다(`txt`, `md`, `docx`, `zip`, `HWP` 등).
     - 가입 메일 주소는 검사에서 뺀다.

## 하지 않는 것

- AI 초안, 방향 조언 같은 다른 기능의 팩은 보이지 않는다. 이번에는 회차 점검만 한다.
- 지난 점검 때 보낸 팩을 저장하지 않는다. 마이그레이션이 필요하다. 보기는 "지금 저장된 원고로 점검하면 보낼 것"이다. 원고를 고치지 않았다면 마지막 점검과 같다.
- 프롬프트 원문을 그대로 보여 주지 않는다. 내부 ref 태그(`[F1]`)와 지시문은 작가에게 의미가 없다.
- AI가 만든 문장(설명, 제안)의 언어는 검사하지 않는다. 프롬프트가 한국어로 쓰라고 이미 지시한다.
- 새 패키지, DB 마이그레이션.

## 설계 판단 (사용자가 맡긴 결정)

- (설계 판단) 새 탭이 아니라 점검 탭 안에 둔다.
  - 탭이 이미 7개다.
  - 점검 결과의 위키 근거와 나란히 봐야 뜻이 있다.
- (설계 판단) 서버 액션으로 읽는다. DB만 읽어 빠르므로 경로 처리기가 필요 없다.
- (설계 판단) 유효 회차 표시는 사실 목록과 같은 글꼴을 쓴다(`3화부터 ~5화`, `3화부터`, `~5화`). 함수 하나로 모아 두 곳이 같이 쓴다.
- (설계 판단) 실행 방식은 지난번과 같다.
  - Opus가 계획을 쓴다.
  - Sonnet 에이전트가 OpenCode를 부려 구현한다. 모델 순서는 deepseek-v4.1-flash-free, glm-5.3-flash-free, muse-spark-1.3-contributor다.
  - 마지막 검토는 Sonnet이 한다.
  - 영어 문구 정리는 다른 파일만 만지므로 따로 병렬로 돈다.
