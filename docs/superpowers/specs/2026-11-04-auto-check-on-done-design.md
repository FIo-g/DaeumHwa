# 완료하면 자동 점검 설계 (2026-11-04)

## 왜

StoryBench 같은 도구는 "저장하면 설정이 쌓인다"는 편의를 내세운다. 다음화는 일부러 승인 구조를 둔다. AI가 뽑은 설정·떡밥 후보는 작가가 승인해야 위키와 떡밥 장부에 들어간다. 이 구조는 지키면서, 후보를 올리는 일은 작가가 따로 버튼을 누르지 않아도 되게 한다.

## 지금 동작 (2026-11-04 코드 확인)

- 저장(`saveChapterAction`)은 원고만 저장한다. 설정이나 떡밥을 뽑는 AI 호출이 없다.
- `회차 점검` 버튼(`POST /api/works/{workId}/chapters/{chapterId}/check` → `runChapterCheck`)이 설정 충돌 점검과 설정·떡밥 후보 추출을 함께 돌린다(`Promise.allSettled`).
  - 지적은 그 회차의 열린 지적을 바꾼다.
  - 후보는 출처 `post_chapter`(화면 이름 `회차 점검`)로 승인 대기에 올라간다. 같은 회차의 승인 전 후보는 새 후보로 바뀐다.
- 승인해야 위키와 떡밥 장부에 들어간다. 자동 승인 옵션은 없다. 인터뷰와 원고 가져오기도 같다.
- 회차 상태는 `초안`/`완료` 두 가지다. 바꾸는 곳은 두 군데다.
  - 집필 화면 도구 막대의 `회차 상태` 버튼
  - 회차 목록 표의 상태 버튼
- 집필 화면에서 `완료` 로 바꾸면 이미 `수정에서 찾은 요청` 추론(`/directives/infer`)이 따로 돈다.

## 할 일

회차를 `초안` 에서 `완료` 로 바꾸는 데 성공하면, 그 회차의 회차 점검을 자동으로 한 번 돌린다. 결과는 평소 점검과 같다. 지적은 점검 탭에 보이고, 후보는 승인 대기에 올라간다.

- 두 곳 모두 적용한다: 집필 화면과 회차 목록.
- 분량이 모자라 `완료하기` 확인을 거친 경우도 같다.
- 집필 화면에서는 `완료` 로 바꾸기 전에 열린 편집을 먼저 저장한다(`saveNow`). 점검과 `수정에서 찾은 요청` 추론이 모두 저장된 원고를 읽기 때문이다.
- 진행과 결과는 토스트로 알린다.
  - 시작: `{N}화를 완료로 바꿨습니다. 회차 점검을 시작합니다.`
  - 끝: `{N}화 점검을 마쳤습니다.`, 설명 `지적 {a}건, 승인 대기 후보 {b}건`.
    - 후보가 있으면 `승인 대기 보기` 버튼을 단다(`/works/{workId}/approvals`).
  - 실패: `{N}화 자동 점검을 하지 못했습니다.`, 설명은 서버 메시지(예: 사용 한도).
  - 취소: `취소했습니다.`
- 집필 화면의 점검 탭은 자동 점검이 도는 동안 `자동 점검 중… {초}초` 와 `취소` 를 보인다. 그동안 `회차 점검` 버튼은 숨긴다.
  - 넓은 화면에서는 자동 점검이 시작되면 옆 패널이 `점검` 탭으로 바뀐다.
  - 끝나면 받은 지적을 바로 보이고, 화면도 새로 고친다(`router.refresh`).
- 점검 탭의 빈 상태 설명: `회차 점검을 누르거나 회차를 완료로 바꾸면 설정과 어긋나는 문장을 찾아 줍니다.`
- README 기능 목록에 한 줄을 더한다.

## 하지 않는 것

- 저장할 때마다 점검하지 않는다. 자동 저장이 잦아 호출이 너무 많아진다.
- 승인 없이 위키에 넣지 않는다. 차별점이 사라지고, 추출이 틀리면 위키가 오염된다. 자체 측정에서도 추출 결과는 같은 조건에서 편차가 컸다(표본이 작은 측정).
- `완료` 에서 `초안` 으로 되돌릴 때, 그리고 이미 `완료` 인 회차에서는 돌리지 않는다.
- 새 패키지, DB 마이그레이션, 서버 쪽 변경은 없다. 이미 있는 점검 경로를 그대로 부른다.
- 샘플 작품 데이터는 바꾸지 않는다. 샘플 회차는 이미 `완료` 이고, 들어가자마자 3화 점검이 돈다.

## 설계 판단 (사용자가 맡긴 결정)

- (설계 판단) 점검은 브라우저가 기존 점검 경로를 부르는 방식으로 돌린다.
  - 이유 1: 서버에서 몰래 돌리면 진행과 실패를 작가에게 알릴 길이 없다.
  - 이유 2: Inngest는 운영에서 켜져 있지 않다.
- (설계 판단) 자동 점검은 화면 부품이 아니라 모듈 하나(`src/lib/client/auto-check.ts`)가 들고 있다.
  - 그래서 완료를 누르고 바로 다음 회차로 넘어가도 점검은 계속 돈다.
  - 탭을 닫거나 새로 고치면 요청이 끊기고, 서버는 그 신호로 점검을 멈춘다.
  - 같은 탭에서 같은 회차의 자동 점검은 한 번에 하나만 돈다.
- (설계 판단) 자동 점검은 위키 후보 대화상자를 저절로 띄우지 않는다. 샘플 자동 점검과 같다. 후보는 승인 대기에서 본다.
- (설계 판단) 원고가 지난 점검 뒤로 바뀌지 않았어도 다시 돌린다.
  - 마이그레이션 없이는 "이 원고 버전으로 점검했다"는 기록이 없다.
  - `초안` 에서 `완료` 로 바꾸는 일은 드물다.
- (설계 판단) 회차 목록에서 여러 회차를 잇달아 `완료` 로 바꾸면 회차마다 점검이 따로 돈다. 한 번에 도는 수는 제한하지 않는다. 사용 한도는 서버가 지킨다(검토 #5, 받아들임).
- (설계 판단) 작가가 수동 점검을 돌리는 중에 `완료` 를 누르면 점검이 두 번 돌 수 있다. 결과는 나중에 끝난 쪽으로 정리된다. 드문 경우라 막지 않는다.
- (설계 판단) 발표 표현: "점검을 돌리면 후보가 자동으로 올라오고, 승인해야 쌓인다." 이 기능이 들어간 뒤에는 "회차를 완료하면 점검이 자동으로 돌고, 후보는 승인해야 쌓인다." "저장하면 쌓인다"고 말하지 않는다.
- (설계 판단) 실행 방식은 지난번과 같다.
  - Opus가 계획을 쓴다.
  - Sonnet 에이전트가 OpenCode를 부려 구현한다. 모델 순서는 deepseek-v4.1-flash-free, glm-5.3-flash-free, muse-spark-1.3-contributor다.
  - 마지막 검토는 Sonnet이 한다.
  - push와 배포는 사용자가 한다.
