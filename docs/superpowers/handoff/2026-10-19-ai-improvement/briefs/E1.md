## Goal

Make "문단은 세 문장을 넘기지 않는다" checkable in code. After a draft is generated, count sentences per paragraph with a pure function, send only the offending paragraphs to a new AI task that rewrites them (one paragraph may become two paragraphs), apply the result, and record how many offenders remain as an eval metric. No signature of an existing function changes except one optional input field on `createChapterFromDraft`.

## Design (do in this order)

Definitions fixed for the whole track: a paragraph is a non-empty trimmed line (same as `chapterMetrics`, eval/novel/metrics.ts:57-60). A sentence is what `splitSentences` returns for that line, after protecting non-terminator dots. Dialogue lines count as paragraphs. Limit is 3 (`PARAGRAPH_MAX_SENTENCES`), a constant, not parsed from the style card.

1. `src/lib/korean/paragraphs.ts` (pure, no AI). Export `PARAGRAPH_MAX_SENTENCES = 3`, `splitParagraphs`, `countSentences`, `overlongParagraphs`, `replaceParagraphs`, `dialogueSpans` (signatures in Interface). `countSentences` first calls the exported `protectNonTerminatorDots(text)`, which replaces ONLY the dot (never the letters) with the same-length private char ``: `text.replace(/(?<=\d)\.(?=\d)/g, '')` for a dot between two digits, and `text.replace(/\b(Mr|Mrs|Ms|Dr|Prof|St|Jr|Sr)\./g, (_m, abbr: string) => `${abbr}`)` for a dot after an abbreviation (a replacer callback that re-emits the abbreviation letters; a plain string replace of the whole match would delete them). The output has the same length as the input. Then `countSentences` returns `splitSentences(protectNonTerminatorDots(text)).length`. Also export `hasOverlongSpan(paragraph, max)`: true when any `dialogueSpans(paragraph)` span has `countSentences(span) > max` (such a paragraph can never pass `isValidTrim`, because the quoted span must stay verbatim; used for the metric in step 9). Do not edit `splitSentences`. `splitParagraphs` uses `text.matchAll(/[^\n]+/g)`, trims each match, skips blank ones, and returns `{index, text, start, end}` with offsets of the trimmed text in the original. `replaceParagraphs` replaces by offsets from the last paragraph to the first; unknown indexes are ignored; all other bytes stay identical. Separator decision: the manuscript convention is a blank line between paragraphs (`\n\n`): `fakeDraft` (src/test/ai-fakes/draft-chapter.ts:25) joins paragraphs with `\n\n`, and the fixture style-card examples (eval/fixtures/novel/ko/bible.json:149) use `\n\n`; the chapter body is shown with `whitespace-pre-line`-style plain text, so a lone `\n` would render as a soft break. So when a rewrite splits one paragraph into two, the two parts are joined with `\n\n` (the task prompt asks for `\n\n`, but a model may answer with a single `\n`, so the task's `postProcess` normalizes every accepted rewrite to `\n\n`, see step 3; `replaceParagraphs` itself inserts the rewrite text as given and never normalizes it). Both parts then count as separate paragraphs for the harness and for the reader. `dialogueSpans` uses `/"[^"\n]+"|“[^”\n]+”|「[^」\n]+」/g` (same shape as DIALOGUE_RE in src/server/ai-features.ts:53).
2. `src/db/types.ts`: append `'paragraph-trim'` to `AI_TASKS`.
3. `src/ai/tasks/paragraph-trim.ts`. Model on proofread.ts. `name: 'paragraph-trim'`, `effort: 'low'`, `maxTokens: 8000`. Do not set `timeoutMs` on the task (decision, see Risks). `PARAGRAPH_TRIM_SYSTEM` (Korean, ends with `TAG_DATA_RULE` and "- 모든 출력은 한국어로 쓴다.") rules: rewrite only the paragraph in `<target>`; at most `<max_sentences>` sentences per line; may split into two paragraphs separated by a blank line (`\n\n`); keep every event, fact, name and quoted dialogue exactly (dialogue in quotes must be copied unchanged); keep the voice and tense; `<before>`/`<after>` are context only, never rewritten; do not add new content; return `index` unchanged. `buildPrompt` uses English tag names only and no Korean label text (EN mode runs `translateScaffold` on it): `<max_sentences>3</max_sentences>` then, per item, `<paragraph index="4"><before>…</before><target>…</target><after>…</after></paragraph>`; a null neighbour renders as empty tag. Run input through `neutralizeDeep`. `isValidTrim(original, rewrite, max)` returns true only if: rewrite is non-empty and differs from original; every non-empty line of rewrite has `countSentences <= max` (a `\n\n` split gives two lines to check); compact length (`text.replace(/\s/g, '').length`) of rewrite is within 0.75 to 1.15 times the original; every `dialogueSpans(original)` span appears verbatim in rewrite. `postProcess(output, input)` keeps only entries whose `index` is in `input.items` (first entry per index). For each kept entry it first normalizes the rewrite: split on `\n`, trim each part, drop blank parts, join with `\n\n` (so a single-`\n` split becomes a `\n\n` split); then it applies `isValidTrim(original, normalized, max)`, and the normalized text is what it returns. It never throws.
4. `src/server/draft-paragraphs.ts`: `trimOverlongParagraphs(db, actor, input, client?, signal?)`. First line `await requireWorkRole(db, input.workId, actor.userId, 'editor')`. `max = input.maxSentences ?? PARAGRAPH_MAX_SENTENCES`. `before = overlongParagraphs(text, max).length`. Loop at most `MAX_TRIM_ROUNDS = 2`: take offenders of the current text; stop if none; build items (neighbour text = adjacent paragraph from `splitParagraphs`, cut to 300 chars, null at the ends); `runAiTask(db, {userId: actor.userId, workId, signal}, paragraphTrimTask, {maxSentences: max, items}, client)`; if `output.paragraphs` is empty stop; else `current = replaceParagraphs(current, output.paragraphs)` and collect `runId`. Return `{text, changed, before, after, rounds, runIds}`. No offenders: return the text unchanged with zero AI calls. `AppError` from `runAiTask` in round 1 propagates (so `withModelRetry` in the eval sees it). In round 2 or later the loop catches `AppError`, stops, and returns the partial text with `after`, `rounds` (the number of rounds started, including the failed one) and the `runIds` collected so far: the valid round-1 rewrites are never thrown away. (An external limit or network error in round 2 is therefore swallowed by the service; the eval hook in step 9 discards the stale failure record.) It never touches wiki tables and never writes the manuscript.

## Risks

- `createChapterFromDraft` reads `ai_runs.output.text`. Without step 5 the eval would review the trimmed text but save the raw draft. Test 24 guards this.
- In the product, a post-stream rewrite would make the saved text differ from the streamed text (ai-features.test.ts:191-208). That is why startDraft and the route are not touched.
- Local models: one call can take 20 to 35 minutes. The product default limit is 120 s (`DEFAULT_AI_TIMEOUT_MS`, src/ai/run.ts:28), and `paragraph-trim` keeps it (no `timeoutMs` on the task, decided). In the eval the profile limit overrides it (`setAiTimeoutOverride`, eval/novel/run.ts:126): 60 min for local models, 15 min for cloud, so a qwen/luna trim call is allowed to finish in the eval; a longer call than that fails; a model failure (bad format) is recorded in `state.failed` and the raw draft is kept, whereas an external failure (limit, network) in round 1 makes `withModelRetry` throw `ExternalFailureError` and the run pauses instead of keeping the raw draft. The trim is skipped when there are no offenders and sends only offenders, so it stays small.
- `createChapterFromDraftAction` does not accept `body` (step 5). Only server code and the eval can save a body that differs from the run's stored text.
- Dialogue-only offenders: a paragraph with one quoted span of more than 3 sentences (for example one `"..."` line with 4 or more internal sentences) can never pass `isValidTrim`, because the span must stay verbatim. The 90% target does not apply to them; `trim.json` reports them as `unfixableDialogue`. There is no baseline for how common they are in the six runs.
- The rewrite can drop facts (T2). `isValidTrim` guards dialogue and length only, not facts. The reviewer still judges T2.
- `splitSentences` splits Korean only at `.!?…`; a Korean sentence without a terminator counts as part of the next one. Accepted, pinned by test 5.
- `fakeDraft` has 5 or more sentences in every paragraph, so every run.test.ts fake draft now triggers a trim; the fake in step 6 must make it valid or existing eval tests fail.
- An extra AI call per attempt shifts call counts in eval tests (`calls/` records). Run the whole eval test folder.

## Open questions

- Product default: should the 3-sentence limit apply to all works, or only when the author's style card says so? This brief uses a constant 3 and an eval-only hook; product UI wiring (a "문단 다듬기" step on the draft panel) is out of scope.
- Rewrite granularity: whole paragraph, possibly split into two lines (chosen). Merging sentences is not supported.
- Still over the limit after 2 rounds: keep the original paragraph and report via `after` (chosen), do not retry the draft. A round-2 AI error keeps the round-1 fixes (step 4).
- Dialogue-only offenders (one quoted span over the limit): exclude from the 90% denominator and report as `unfixableDialogue` (chosen), or allow splitting inside a quote (not allowed: dialogue must stay verbatim).
- English counting uses the small abbreviation list in step 1; extend it only if the en runs show false positives.
