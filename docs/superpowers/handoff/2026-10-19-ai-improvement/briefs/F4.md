# F4. Local server serialization and helper think switch (LOCAL branch)

Re-pointed on 2026-10-19 at the code of `feat/ai-improvement-local` (cloud tracks A, B, E1, E2, G1, G2, H, I, J, GUARDS, HX1-HX5 merged; Wave L0 seam in place). Wave L1 runs F4 in parallel with F3 and F1. Find code by name; line numbers below are for this tip and move.

## Goal

Two eval-harness changes for local (Ollama) models, plus honest accounting:

1. Never run two AI calls at once against one local server. Today continuity-check and chapter-extract run together (`Promise.allSettled` in `runChapterCheck`), so one waits behind the other inside Ollama, and the waiting time is counted as call time.
2. Add a switch to run helper tasks (every AI task except the prose-writing ones, see `PROSE_TASKS`) with a lower `think` setting, so a compare run can test the hypothesis that less thinking keeps helper quality and cuts time.

Terminology: in this track "effort" (as in the follow-up doc's F section, `docs/eval/novel/follow-up-ai-improvement.md` lines 82-91) means Ollama's `think` setting for helper tasks. `AiEffort` is not forwarded to Ollama and must not be wired in or changed.

Both changes live in the eval harness and in the Ollama client. The product path (`src/server/chapter-check.ts`, `src/ai/run.ts`, `src/server/ai-features.ts`) is NOT changed. Product code never builds `OllamaAiClient` (only `eval/novel/models.ts` does), so no product behaviour changes.

Pattern: `const prev = this.lane; let release!: () => void; this.lane = new Promise<void>((r) => (release = r)); await prev; return release`. `generateObject` must call `acquire` before its first `await`, so the lane order is the call order.

   - `streamText` stays unlocked. ## Risks

- Lane is per EvalClient (per process, per run dir). Two runs against one Ollama still contend; the existing worker lock (`eval/novel/worker-lock.ts`) is per run dir only. Out of scope; the novel-eval skill should keep one local model running at a time (model-setup.md:30).
- `think: false` on gpt-oss is ignored by Ollama (it needs a level). `checkHelperThink` rejects `off` there, so a run never records a `thinkRequested: false` that was not applied. Non-Ollama profiles and exaone reject `--helper-think` for the same reason (nothing to apply).
- Moving `prepare()` after the lane changes `seq` order to lane order. Call files are named by seq, so numbering stays unique and increasing; only which parallel call gets the lower seq may differ from before.
- A queued call keeps the product deadline timer that `runAiTask` started before the client call (`callSignals`), so its time limit includes the wait; in eval the limit is the 3,600,000 ms override. A queued call whose sibling aborted stops waiting at once (the lane wait is raced against `args.signal`) and is recorded as a failed call; its lane slot is released only after the head call ends, so later calls still wait for the head call.
- Lower think may hurt helper accuracy (unverified). Default stays unchanged, so existing runs and baselines are not affected.
