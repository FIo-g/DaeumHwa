## Goal

Five code-side fixes for the settings extraction, all pure code, no second AI call:
1. Interview extraction receives the work's existing and pending facts (`<known_facts>`) and a system rule not to repeat them.
2. Near-duplicate facts are dropped in code against the work's existing facts (interview, import, chapter check) with `isNearDuplicateFact` imported from `@/ai/guards` (GUARDS owns it, this track writes no similarity code). In import, repeats across chapters of the same job stay exact-only (see out of scope).
3. Evidence quotes (facts, threads, relations) must appear verbatim in the source text; otherwise the item is dropped. Whitespace differences are tolerated and the stored evidence becomes the exact source slice.
4. An interview answer that only says "아직 정하지 않았어요" (any sentence-level variant) skips the AI call and creates no proposals. `isUndecidedOnlyAnswer` is built on I's `isUndecidedAnswer` pattern list (`src/lib/interview-plan.ts`), no second regex list.
5. `extractionToProposals` fills the `dropped` counters `{ duplicateFacts, unverifiedEvidence }` that G2 added as zeros (spec 6 shape `{ proposals, pendingThreadEvents, stats, dropped }`).

Out of scope: same-job cross-chapter near-duplicates in import (`dropRepeatedProposals` in `src/server/imports.ts` keeps its exact `collapseSpaces` key; only wiki facts are checked near-duplicate there). Out of scope (other tracks): name truncation, relation endpoint gating, planted-thread forcing (G2); the shared guard library (GUARDS); harness metrics (HX*).

## Design (do in this order, each step test-first)

Write no similarity code. Sentences this track's tests rely on (GUARDS calibrates them): reworded `종루의 종은 밤마다 떨린다.` vs `종루의 종은 밤마다 떨린다고 한다.` is a duplicate; `서윤은 열일곱 살이다.` vs `서윤은 열여덟 살이다.` and `서윤은 검을 쓴다.` vs `서윤은 검을 쓰지 못한다.` are not. 2. `src/lib/evidence-quote.ts`: pure `verifyEvidenceQuote(source, evidence): string | null`.
   - `const quote = evidence.trim()`; empty => null.
   - Try `locateQuote(source, quote)`; if null try `locateQuote(neutralizeTags(source), quote)` (the model saw the neutralized text, where `</x` became `＜/x`; same length, so offsets stay valid).
   - Found => return `source.slice(start, end)` (raw source slice, so whitespace variants are repaired). Not found => null. Case-sensitive, never fuzzy.
3. `src/lib/undecided-answer.ts`: pure `isUndecidedOnlyAnswer(answer): boolean`, built on I's `isUndecidedAnswer` (import from `@/lib/interview-plan`; do not copy its patterns).
   - Split with `splitSentences`. It splits after every `.!?…` run, so `음... 아직 정하지 않았어요.` becomes `음...` and `아직 정하지 않았어요.`. The implementer runs `splitSentences('음... 아직 정하지 않았어요.')` once to confirm.
   - Classify each sentence: `filler` when the compact form (lowercase, remove `[\s.,!?…~"'“”‘’]`) matches `/^(음+|어+|흠+|글쎄요?)$/` (checked first, anchored, linear); `marker` when `isUndecidedAnswer(sentence.text)` is true; else `other`.
   - Return true only when there is no `other` sentence and at least one `marker`. A topic-prefixed sentence such as `결말은 아직 정하지 않았어요.` is matched by I's list, so it skips extraction (nothing to extract in it); a mixed answer with a content sentence is never skipped. If I's patterns change, adjust only the topic-prefixed expectations in this track's test.

- Dice 0.8 may still miss paraphrases; the prompt rule is the main fix and the code filter is a safety net. Digit guard misses Korean numerals (`열일곱`), so a long fact changing only a numeral could be dropped; accepted, the threshold is conservative.
- `ExtractionContext` fields are optional and the new `dropped` return field is additive, so existing callers and tests keep compiling. `InterviewExtractInput.knownFacts` is required, so every literal must be updated (at b4d49a9: `src/ai/tasks/interview.test.ts` helper, the `localize` sample literal, `e2e/ai-stub/responders.test.ts` tuple; the grep in Files finds the rest; see step 11).
