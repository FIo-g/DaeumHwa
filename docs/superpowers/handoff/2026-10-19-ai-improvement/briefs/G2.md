## Goal

Three code-only fixes in the pure proposal mapper `extractionToProposals` (all three entry points, chapter check, interview answer and import, go through it):
1. A character name that is only the tail of an existing/pending/same-extraction character card name (세린 for 한세린) is rewritten to the card's full name before dedupe, so no truncated card is proposed and facts/relations bind to the real card.
2. A `relation_create` whose source or target matches no card anywhere (wiki, pending `entry_create`, or created in this extraction) is not proposed.
3. A mention of a `planned` thread (open thread planted only in the interview) is recorded as `planted` even when the model gave kind `developed`/`resolved` with no usable ref (title match).
Plus: pass `pendingEntries` in the import path (otherwise fix 2 would drop valid relations there), and one prompt line telling the model to use full card names. G2 also fixes the shared return shape `{ proposals, pendingThreadEvents, stats, dropped }` (spec 6): it adds `stats` and a `dropped` object that is always present and always zero here; G1 (wave 3) fills `dropped`.

## Interface (TypeScript)

```ts
// src/ai/extraction.ts
export type ExtractionDropped = {
  /** Always 0 in G2. G1 counts near-duplicate facts dropped. */
  duplicateFacts: number
  /** Always 0 in G2. G1 counts items dropped for evidence not found in the source. */
  unverifiedEvidence: number
}

export type ExtractionStats = {
  /** Names rewritten from a tail fragment to a full card name (counts entries, fact subjects and relation ends). */
  fragmentNamesFixed: number
  /** relation_create candidates dropped because an end matched no card. */
  relationsDropped: number
}

export function findFragmentCanonical(
  name: string,
  kind: EntryKind | undefined,
  cardNames: readonly string[],
): string | undefined

export function extractionToProposals(
  x: Extraction,
  ctx: ExtractionContext,
): {
  proposals: NewProposal[]
  pendingThreadEvents: PendingThreadEvent[]
  stats: ExtractionStats
  dropped: ExtractionDropped
}
```

## Risks

- False merge: a genuinely new character whose name is the tail of an existing 3-4 syllable name (a different 세린) is merged. Mitigations: unique match only, tail only, length difference 1-2, character kind only. Accepted.
- Same-extraction surname merge: if one chapter extracts two different characters that differ only by a surname (`서윤` and `김서윤`), the shorter one is rewritten to the longer one, because the extraction name is a rewrite target and the candidate's own name is excluded from the exact-card check (step 2). Test 4 (`[세린, 한세린]`) requires exactly this rewrite, so code cannot tell the two cases apart. Accepted; test 17 pins it.
- A relation whose end is a truncated place name (`종루` for `잿빛 종루`) is dropped, not rewritten, so the author loses that relation until the place is named in full. This is an explicit accepted trade-off of decision (a) plus step 5, not a side effect; test 16 pins it, and the prompt line (step 9) is the only mitigation.
- `stats` is returned but no caller reads it yet; eval wiring (`runChapterCheck` return) is out of scope.
- Dropping a relation loses a real relation if the model forgot the entry. Accepted; the model prompt already says entries hold new people. The approval-time check remains.
