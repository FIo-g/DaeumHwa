## Goal

AI proofread sends the whole chapter in one call. On local qwen that call thinks until the output cap and runs far past the 120 s product limit. Cut the text into up to three parts, call the existing `proofread` task once per part, one after the other, merge the model's suggestions (the task has already checked that each quote lies inside its own part), and then run J's quote location (`expandQuote` plus the overlap guard) ONCE on the whole text, so offsets are whole-text offsets from the start and J's behavior (every exact occurrence with the same word-boundary context as the first one, cap of 20 per quote, no overlaps) holds for the chapter, not per part. Prompt, schema, effort, maxTokens, API shape and UI stay the same. Short text keeps exactly one call.

## Design (do in this order)

0. Run the Precondition checks. Then read `chapter-check.ts` lines 84-157 and keep J's behavior exactly: `expandQuote(text, quote)` finds all exact occurrences of a quote of 2+ characters with `locateAllQuotes(text, quote, Number.MAX_SAFE_INTEGER)`, keeps those whose before/after word-character context equals the first occurrence's (`boundaryOf`; so `할수` does not expand into `할수록`), and takes the first 20 (`MAX_QUOTE_EXPANSION`); a shorter quote or one found only after whitespace collapse maps to `locateQuote`'s first hit. In `check`, an `emitted` list drops any range that overlaps an earlier AI range (model output order). Expansion must run on the WHOLE text, never per part (`briefs/J.md` step 4 and Dependencies).
1. TDD: write `src/lib/korean/proofread-parts.test.ts` first (cases below), see it fail, then create `src/lib/korean/proofread-parts.ts` with `splitProofreadParts` (pure, no imports from server code).
   - `count = Math.min(maxParts, Math.max(1, Math.floor(text.length / minPartChars)))`. Defaults: `maxParts = 3`, `minPartChars = 1500`. So under 3,000 chars: 1 part; 3,000 to 4,499: 2 parts; 4,500 and more: 3 parts. Empty text: one part `{start:0,end:0,text:''}`.
   - Start with `cuts = []` (the accepted cut indices, strictly increasing) and `prevCut = 0` (the previous accepted cut; 0 before the first). For `i = 1..count-1`: `target = Math.round(text.length * i / count)`, `window = Math.floor(text.length / count / 3)`, `lo = Math.max(prevCut + 1, target - window)`, `hi = Math.min(text.length - 1, target + window)`. A cut index `p` must satisfy `1 <= p <= text.length - 1` and `p > prevCut`. With the default arguments `lo <= hi` always holds; if it does not (custom small arguments only), use `p = hi` and drop the cut when `p <= prevCut`. After choosing `p`, push it to `cuts` and set `prevCut = p`. Candidate cut index `p` (cut falls before `text[p]`) in `[lo, hi]`, in three tiers: tier 1 = the text before `p` ends with a blank line (regex `/\n[ \t\r]*\n$/` on `text.slice(Math.max(0, p - 20), p)`); tier 2 = `text[p - 1] === '\n'`; tier 3 = `text[p - 1]` is one of `.!?…"'”’」』)` and `text[p]` is not one of those characters. Take the lowest tier that has a candidate and, inside it, the candidate nearest to `target` (ties: the smaller index). Tier 4 (no candidate): `p = target`, moved by +1 when `text[p-1]` is a high surrogate and `text[p]` is a low surrogate; clamp to `[lo, hi]`.
   - Parts are contiguous: part `k` is `text.slice(cuts[k-1] ?? 0, cuts[k] ?? text.length)`; `part.text === text.slice(part.start, part.end)`; joining all part texts gives the input exactly. Cuts are strictly increasing.
2. Add to the same file `mergeSuggestionGroups` (pure, generic over `{ quote: string; replacement: string }`): concatenate the groups in part order (model order inside each group) and drop later items that repeat an earlier one with the same `quote` and `replacement` (keep the first). No offsets are involved: the model's suggestions carry no offsets, and offsets are computed once on the whole text in step 4. Reason for the dedupe: the same quote can be returned by two parts, and the whole-text expansion already finds every occurrence, so the second item would only produce overlapping ranges.

Then, inside `check(text)`:

   - `partTimeout = parts.length > 1 ? Math.min(DEFAULT_AI_TIMEOUT_MS, Math.floor(PROOFREAD_TOTAL_BUDGET_MS / parts.length)) : undefined` (3 parts give 95,000 ms, 2 parts 120,000, 1 part undefined so the call is identical to today).

## Risks

- Split cost: three calls repeat the system prompt and the fixed thinking cost. qwen en spent 696 s on an empty result, so total time may not fall. Hypothesis only; measure later. The 1,500-char minimum part size limits waste on short text.
- Token cost and daily limit: a split proofread repeats the system prompt in each call (about 3x the fixed input overhead) and each part checks `AI_DAILY_TOKEN_LIMIT` separately. If the limit is reached after part 1 or 2, the call fails with `AI_LIMIT` and the tokens already spent on earlier parts are lost with no result. Accepted for this track (no pre-check before the loop); the orchestrator may overrule.
- Throughput arithmetic: qwen ko produced 18,899 output tokens in 1,497 s, about 12.6 tokens/s. In 95 s that is roughly 1,200 tokens. A third of a chapter needs far more than that if the model thinks as long as it does now (one third of 18,899 is about 6,300 tokens, about 500 s). So the split alone will probably NOT bring local qwen under 95 s per part; it only shrinks each call and cuts the chance of hitting the output cap. The speed fix belongs to F4 (helper think switch) and the model/server choice.
- 95 s per part on a slow local server can fail where 120 s would not, and one part timeout fails the whole call (failure policy). Decision: the track ships anyway, because the 300 s route limit forces the per-part budget and because short text and cloud models are unaffected. Go/no-go for later: if local qwen parts still exceed 95 s after F4, the next options are lower effort, more parts (needs a new decision), or a smaller per-call cap; the eval run must show total proofread time and the failed-part count before anyone changes the numbers. Eval ignores the per-part limit (`timeoutOverrideMs` wins).
- Quotes spanning a cut are lost. Cuts prefer blank lines and newlines; no overlap windows (kept simple).
- A quote that one part flags is also applied to every same-context occurrence in the other parts (whole-text expansion, J's rule), even where that part's model call did not flag it. Same as one call today, and the author decides in the panel.
- `runId` is now the last part's run only; `runIds` lists all. Panel and action use only `runId`, so they keep working. The eval records only `proofed.suggestions` and does not use `runId` or `runIds`.
- A failing part loses the other parts' suggestions (previous behavior was all-or-nothing too).
- Dedupe by quote and replacement keeps the first item only; if the model returns the same quote with a different `kind` or `reason` in two parts, the later one is dropped (same ranges would collide in the overlap guard anyway).
- `'가'.repeat(30000)` in the cap tests has no boundaries: hard cuts. Fine, but the fake returns empty suggestions for every part.
- Do not touch `process`-wide state (`setAiTimeoutOverride`) in tests.
