# Brief E2: sample-copy and repeated-word check (cloud branch)

Reader: haiku, TDD, isolated worktree. Read-only survey is done; every path below was re-checked against the code on 2026-10-19. Line numbers are from the current `main` and may shift by a few lines after your edits.

## 1. Goal

1. Add pure code that finds (a) draft sentences that copy or near-copy a style-card sample sentence and (b) words/phrases repeated too often.
2. Add one rule line to the draft system prompt, Korean and English twin: `견본은 어조만 참고하고, 문장과 이미지를 베껴 쓰지 않는다.`
3. Add a new AI task `draft-repair` that rewrites ONLY the flagged sentences (quote and replacement edits, like proofread). Code verifies every edit lies inside a flagged span before applying it.
4. Expose it as a service `repairDraft` + server action (no UI button in this track), call it in the eval draft step, and add two eval metrics so the next eval round can measure the effect.

## 2. Evidence (numbers; all from reviews in `docs/eval/novel/2026-10-18/`, hand counts, no code baseline exists)

- Sample sentences copied almost verbatim in 5 of 6 runs (`summary.md:135,238`). Not exact substrings in most cases: haiku ko body `쇠가 손바닥에 달라붙을 만큼 차가워서` vs sample `쇠가 손바닥에 들러붙을 만큼 차가웠다.` (`haiku-5.5-ko.md:118`); qwen ko verbatim `안개가 계단을 반쯤 삼키고 있었다.` (`qwen3.8-27b-ko.md:165-166`); haiku en verbatim `The iron was cold enough to stick to her palm` (`haiku-5.5-en.md:35`); luna en 2 paraphrases (`luna-6-en.md:68`).

- Offline check I ran: char-3-gram containment of the example sentence inside the draft sentence (letters and digits only, lowercase): haiku ko pair 8/14 = 0.57; verbatim 1.00; unrelated ko pairs 0.00; en verbatim 1.00; en unrelated 0.18 (the `Mina climbed the stairs...` pair in section 6; 6/34). Threshold 0.5 and minimum 10 normalized chars separate them.

## 4. Design (do the steps in order, tests first for each)

Why not hook into the stream: `startAiStream` (run.ts:135) streams text to the client before `done`, so a rewrite cannot change what the client already got. So repair is a separate call after the draft run is done, and it rewrites the stored run output, which `createChapterFromDraft` (ai-features.ts:365) reads.

1. `src/lib/korean/style-copy.ts`: type `DraftFlag` and helper `normalizeForCopy(s)` = lowercase, keep only `\p{L}\p{N}` characters.
2. Same file, `findSampleCopies(text, examples, opts?)`: split every example with `splitSentences` (examples string may hold several lines). Skip example sentences whose normalized length is under `minChars` (default 10). For each draft sentence (from `splitSentences(text)`), compute containment on distinct 3-grams: build a `Set` of the normalized example sentence's char-3-grams and a `Set` of the normalized draft sentence's char-3-grams; containment = (how many of the example set's members are in the draft sentence's set) / (size of the example set). Never count duplicates (the offline check 8/14 = 0.57 assumes sets; the paraphrase test pins it). Flag the draft sentence when containment >= `minOverlap` (default 0.5). One flag per draft sentence. Flag `start/end/quote` come from the sentence (offsets in `text`), `kind: 'sample-copy'`, reason `견본 문장과 거의 같다.`
3. Same file, `countRepeatedWords(text, opts?)` returns `{ word, count }[]` for words with count >= `minCount` (default 8), sorted by count desc then word asc.
   - ko: tokens from regex `/[가-힣]{2,}/g`; `word = stripJosa(token)`; skip when `word.length < 2`, when `word` matches `/[다고며면니네요죠까]$/` (verb or adjective endings; known trade-off: this also skips nouns such as 바다, 가면, 그네, so a repeated 바다 is never flagged; keep the rule simple and pin it with a test), when `word` is in `EXEMPT_KO`, or when it is in `opts.exempt` (compare after `stripJosa`).
   - `EXEMPT_KO` = `그녀 그는 그가 그의 그리고 하지만 그러나 그때 이제 다시 아니 그냥 정말 이미 모두 지금 여기 거기 우리 자신 사람`.
   - en (`opts.lang === 'en'`): tokens from `/[A-Za-z']+/g` lowercased; count bigrams of adjacent tokens where neither token is in `EN_STOP` and each token has 3+ letters. `EN_STOP` = `the and was were did not had has have her his she they that with for but from said this then them there when what into over`. `left hand` must count; `did not` must not. `opts.exempt` also applies to en: lowercase the exempt entries (and their individual words) into a set and skip any bigram where either token is in it, so a recurring name pair such as `serin said` is not counted (exempt entries are wiki names such as `Serin`, while en tokens are lowercased).
4. Same file, `findRepeatedWords(text, opts?)`: for each word from step 3, take its occurrences in text order; skip the first `keep` (default 3); for each remaining occurrence make a flag over the whole sentence containing it (`sentenceIn(splitSentences(text), index)`), `kind: 'repeated-word'`, reason `같은 말 반복: '<word>' <count>번`. One flag per sentence (if several words hit the same sentence, keep the word with the highest count). Cap at `maxFlags` (default 12), earliest first. Return sorted by `start`. Export `RepeatedWordOptions` with `lang, minCount, keep, maxFlags, exempt`.
5. Same file, `findDraftFlags(text, o)`: `findSampleCopies` flags first, then repeated-word flags that do not overlap any sample-copy flag, sorted by `start`, max 20 total. `o = { examples, exempt, lang }`. Add `export * from '@/lib/korean/style-copy'` to `src/lib/korean/index.ts` (check no name clash).

// src/lib/korean/style-copy.ts
export type DraftFlagKind = 'sample-copy' | 'repeated-word'
export type DraftFlag = { kind: DraftFlagKind; start: number; end: number; quote: string; reason: string }
export type RepeatedWordOptions = { lang?: 'ko' | 'en'; minCount?: number; keep?: number; maxFlags?: number; exempt?: readonly string[] }
export function findSampleCopies(text: string, examples: readonly string[], opts?: { minOverlap?: number; minChars?: number }): DraftFlag[]
export function countRepeatedWords(text: string, opts?: Pick<RepeatedWordOptions, 'lang' | 'minCount' | 'exempt'>): { word: string; count: number }[]
export function findRepeatedWords(text: string, opts?: RepeatedWordOptions): DraftFlag[]
export function findDraftFlags(text: string, o: { examples: readonly string[]; exempt?: readonly string[]; lang?: 'ko' | 'en' }): DraftFlag[]

// src/ai/tasks/draft-repair.ts
export type DraftEdit = { quote: string; replacement: string }
export type DraftRepairInput = { text: string; flags: DraftFlag[] }
export type DraftRepairOutput = { edits: DraftEdit[] }
export const DraftRepairSchema: z.ZodType<DraftRepairOutput>
export const DRAFT_REPAIR_SYSTEM: string
export const draftRepairTask: AiTaskDef<DraftRepairInput, DraftRepairOutput>

// src/server/ai-features.ts
export type RepairDraftResult = { runId: string; text: string; flagged: number; applied: number }

// eval/novel/metrics.ts
export type ChapterMetrics = { /* existing fields */ sampleCopyHits: number; repeatedWords: { word: string; count: number }[] }

## 9. Risks

- False positives: a fight scene may need `오른손`. Mitigated by threshold 8, keep first 3, `exempt` (wiki names and aliases), and because repair only rewrites; the author still decides to create the chapter.
- Card examples are verbatim dialogue by design (plan line 645) and `DRAFT_SYSTEM` line 10 says to follow examples. The new rule is the backlog's exact wording. Short examples (under 10 normalized chars) are never flagged, so catchphrases survive.
- Local models are slow (20 to 35 min per call). The eval step adds one structured call (`draftRepairTask.timeoutMs` 180 s, applied in the eval through `TASK_DEFS`); local runs belong to the local branch. A repair that fails or times out keeps the draft and shows up in `state.failed` (step 15), so it is visible in the eval report.
- The run output now has an optional `repair` and `originalText` key. `draftText` (reads `text`) is the product reader. One more reader: `src/server/exports.ts:128-138` writes done `draft-chapter` runs as raw JSON into the backup (`aiRuns`, line 186), so a repaired run's backup now carries `originalText` and `repair`, roughly doubling that run's stored draft text. Decision: accepted, no code change (it only affects repaired runs, and the original text is useful provenance); do not touch `exports.ts`.
- Changing `DRAFT_SYSTEM` moves the eval baseline; the next measurement needs a new date folder.
- Concurrent `repairDraft` calls on the same run (eval retry wrapper plus a user action) can both see no `repair` key, both call the AI (double usage charge) and the second write wins. Known limit; this track does not add a row lock. Not reachable in the eval (one call per attempt).
- English bigram detection is approximate (stop list); it only feeds eval metrics and flags, never blocks.
