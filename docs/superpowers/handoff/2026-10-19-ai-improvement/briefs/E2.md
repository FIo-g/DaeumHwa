## 1. Goal

1. Add a thin wrapper that turns the GUARDS detectors into draft flags: (a) draft sentences that copy or near-copy a style-card sample sentence (`sampleCopies`) and (b) words/phrases repeated too often (`repeatedWords`).
2. Add one rule line to the draft system prompt, Korean and English twin: `견본은 어조만 참고하고, 문장과 이미지를 베껴 쓰지 않는다.` (wording "베껴 쓰지 않는다", see section 10). This is E2's own added line; do not edit lines written by A or other tracks.
3. Fill the pre-registered `draft-repair` task (task name, English module, fake and sample placeholders come from the Wave-0 seam): it rewrites ONLY the flagged sentences (quote and replacement edits, like proofread). Code verifies every edit lies inside a flagged span before applying it.
4. Expose it as a service `repairDraft` + server action (no UI button in this track), call it in the eval draft step, and add two eval metrics so the next eval round can measure the effect.

## 4. Design (do the steps in order, tests first for each)

Why not hook into the stream: `startAiStream` (run.ts:135) streams text to the client before `done`, so a rewrite cannot change what the client already got. So repair is a separate call after the draft run is done, and it rewrites the stored run output, which `createChapterFromDraft` (ai-features.ts:365) reads.

1. `src/lib/korean/style-copy.ts`: type `DraftFlag` and the wrapper functions below. Imports: `sampleCopies`, `repeatedWords`, `splitSentencesFor`, `Lang` from `@/ai/guards`; `sentenceIn` from `@/lib/korean/sentences`; `stripJosa` from `@/lib/korean/josa`. Do NOT tokenize, normalize, compute similarity or count words here: that is GUARDS' job, and a second detector is forbidden (spec 6). The only logic E2 adds is mapping hits to flags, the thresholds, a post-filter over the returned word list (step 3) and the flag selection rules.
2. Same file, `findSampleCopies(text, examples, opts?: { lang?: Lang; threshold?: number; minChars?: number })` = `sampleCopies(text, [...examples], { lang, threshold: opts?.threshold ?? 0.5, minChars: opts?.minChars })` mapped to `DraftFlag`: `start/end` from the hit, `quote: hit.text`, `kind: 'sample-copy'`, reason `견본 문장과 거의 같다.`. GUARDS splits multi-line example strings, ignores sentences under its `minChars` (ko 10, en 24) and returns one hit per draft sentence. The threshold is 0.5, not GUARDS' default 0.6 (section 2: the haiku pair scores 0.54).
3. Same file, `countRepeatedWords(text, opts?)` returns `{ word, count }[]` sorted by count desc then word asc. It calls an internal `repeatedWordHits(text, opts)` (also used by step 4) that wraps `repeatedWords(text, { lang, minCount: opts.minCount ?? 8, ngram: lang === 'en' ? 2 : 1, allow })` and then post-filters its result list (never re-counts):
   - ko: `allow` = `EXEMPT_KO` plus `opts.exempt`, each passed through `stripJosa`. Drop hits whose `word` matches `/[다고며면니네요죠까]$/` (verb or adjective endings; known trade-off: this also drops nouns such as 바다, 가면, 그네, so a repeated 바다 is never flagged; pin it with a test).
   - `EXEMPT_KO` = `그녀 그는 그가 그의 그리고 하지만 그러나 그때 이제 다시 아니 그냥 정말 이미 모두 지금 여기 거기 우리 자신 사람`.
   - en: GUARDS `ngram: 2` pairs adjacent tokens without any stop-word filter, so drop hits where either token is in `EN_STOP` or has fewer than 3 letters. `EN_STOP` = `the and was were did not had has have her his she they that with for but from said this then them there when what into over`. `left hand` must count; `did not` must not. Also lowercase `opts.exempt` entries and their individual words into a set and drop any pair where either token is in it, so `serin said` is not counted (GUARDS `allow` only matches the whole pair).
4. Same file, `findRepeatedWords(text, opts?)`: for each hit from step 3 take `positions` (UTF-16 starts, text order) from GUARDS; skip the first `keep` (default 3); for each remaining position make a flag over the whole sentence containing it (`sentenceIn(splitSentencesFor(text, lang), position)`), `kind: 'repeated-word'`, reason `같은 말 반복: '<word>' <count>번`. One flag per sentence (if several words hit the same sentence, keep the word with the highest count). Cap at `maxFlags` (default 12), earliest first. Return sorted by `start`. Export `RepeatedWordOptions` with `lang, minCount, keep, maxFlags, exempt`.

## 9. Risks

- False positives: a fight scene may need `오른손`. Mitigated by threshold 8, keep first 3, `exempt` (wiki names and aliases), and because repair only rewrites; the author still decides to create the chapter.
- Card examples are verbatim dialogue by design (MVP plan, style-card task) and `DRAFT_SYSTEM` tells the model to follow the style card. The new rule line uses the wording 베껴 쓰지 않는다 (section 10). Short examples (GUARDS `minChars`: ko 10, en 24 normalized chars) are never flagged, so catchphrases survive.
- Detector drift: because E2 depends on GUARDS, a later GUARDS change (normalization, `minChars`, tokenization) moves the flags. The tests in section 6 pin the wrapper's behavior on the quoted strings, so such a change fails them visibly instead of silently shifting the metric.
- Local models are slow (20 to 35 min per call). The eval step adds one structured call (`draftRepairTask.timeoutMs` 180 s, applied in the eval through `TASK_DEFS`); local runs belong to the local branch. A repair that fails or times out keeps the draft and shows up in `state.failed` (step 15), so it is visible in the eval report.
- The run output now has an optional `repair` and `originalText` key. `draftText` (reads `text`) is the product reader. One more reader: `src/server/exports.ts` (`EXPORTED_AI_TASKS`) writes done `draft-chapter` runs as raw JSON into the backup (`aiRuns`), so a repaired run's backup now carries `originalText` and `repair`, roughly doubling that run's stored draft text. Decision: accepted, no code change (it only affects repaired runs, and the original text is useful provenance); do not touch `exports.ts`.
- Changing `DRAFT_SYSTEM` moves the eval baseline; the next measurement needs a new date folder.
- Concurrent `repairDraft` calls on the same run (eval retry wrapper plus a user action) can both see no `repair` key, both call the AI (double usage charge) and the second write wins. Known limit; this track does not add a row lock. Not reachable in the eval (one call per attempt).
- English bigram detection is approximate (stop list); it only feeds eval metrics and flags, never blocks.
