## 1. Code facts that shape the change (cited)

- Ollama ignores `effort`. `src/ai/ollama.ts` has no reference to `effort` at all (grep confirms). `generateObject`/`streamText` pass only the settings given at construction. `think` comes from `this.settings.think` in `chatBody` (src/ai/ollama.ts:397). `OllamaOptions.think` is per client (src/ai/ollama.ts:48). So a "lower effort for helper features" switch cannot reuse `effort` on Ollama. It needs a per-call or per-task think override.
- Eval passes profile effort to the inner client, but Ollama drops it. `eval/novel/eval-client.ts:360` and `:384` send `effort: this.profile.effort`. `eval/novel/models.ts:45` (qwen effort 'max') and `:48` (`think: true`) show think is set separately.
- Timeouts. Product default is `DEFAULT_AI_TIMEOUT_MS = 120_000` (src/ai/run.ts:28). The limit chain is `timeoutOverrideMs ?? meta.timeoutMs ?? task.timeoutMs ?? DEFAULT` (src/ai/run.ts:93). Streams use 280_000 (src/ai/run.ts:30). The eval sets the override to `profile.timeoutMs` (LOCAL = 3_600_000, eval/novel/models.ts:35) in eval/novel/run.ts:126. So in eval, a local call is not actually cut at 120 s. The 120 s only appears as the recorded `productTimeoutMs` label, from `TASK_DEFS.find(...).timeoutMs ?? DEFAULT` (eval/novel/eval-client.ts:439-441, record at :452-455). `src/ai/tasks/continuity-check.ts` and `chapter-extract.ts` set no `timeoutMs`, so they get 120 s. Only imports set one (src/server/imports.ts:288, 240_000).
- Concurrency. `runChapterCheck` runs continuity and extract in parallel with `Promise.allSettled` (src/server/chapter-check.ts:163-183). A sibling AbortController joins the two (src/server/chapter-check.ts:135-137 and the `.catch` at :171-172 and :180-183). The eval check step calls this same function with `ctx.client` (eval/novel/steps/chapter.ts:263-269). Serializing it therefore changes product and eval behaviour. The eval continuity step (chapter.ts:280-320) is separate and already sequential.
- The F4 backlog wording is at docs/eval/novel/follow-up-ai-improvement.md:84-90. It asks for: no concurrent continuity+extract on the same local server, and a lower-effort comparison (hypothesis). Nothing in the repo implements either yet. `eval/novel/steps/finish.ts:52-53` comments that continuity and extract "run in parallel". That comment goes stale once serialized.
- Helper profile fields. `RunConfig`/`createRun` options (eval/novel/run.ts:79-86) have no helper-effort or helper-think field. A new field needs state.ts / cli.ts plumbing.
