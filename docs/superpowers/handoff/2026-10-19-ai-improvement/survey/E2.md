### 4. What could regress
- **Token limits:** `DRAFT_MAX_TOKENS = 16000` (`draft-chapter.ts:17`). Adding rules does not change this. A span-rewrite task needs its own `maxTokens` and must not exceed the output quota on local (qwen previously hit 32,000 output tokens on proofread, per `summary.md`).
- **120 s product timeout:** only structured calls use 120 s (`run.ts:28`). Drafts use 280 s (`run.ts:30`). A structured repair task inherits 120 s unless it sets `timeoutMs`. Local repair calls will not fit 120 s.
- **Prompt-injection neutralization:** draft style data goes through `neutralizeDeep` (`draft-chapter.ts:37`). Any repair prompt that embeds draft text must call `neutralizeTags` (as `proofread.ts` does) and carry `TAG_DATA_RULE` in its system prompt. The sample-copy detector must compare RAW examples to avoid a false negative from `＜` substitution (`prompt-utils.ts:12`).
- **Streaming:** the draft text already reached the client. A post-hoc repair cannot change it without a replace framing. `done` resolves only after the stream ends (`run.ts:167`). Route waits on `done`. Adding a replace record touches `src/lib/draft-stream.ts`, shared with the panel.
- **Stored output drift:** `ai_runs.output` must carry the final text, or `createChapterFromDraft` saves the wrong draft.
- **Eval comparability:** `startDraft` is used by `eval/novel/steps/chapter.ts:112`. A second pass changes the attempt files, so the new run needs a new date (backlog section 1).
