## 3. Code facts that change the design
- Local calls are serialized: docs/eval/novel/README.md:130 says "로컬에서는 Ollama가 한 번에 하나만 처리하므로 병렬 호출 하나가 다른 호출을 기다린다" and "호출 시간에는 큐 대기가 들어 있다". Parallel calls on one local Ollama will not cut wall time and will raise each call's measured durationMs (eval-client.ts:490 computes wouldTimeOut from durationMs, so queue wait counts). Splitting helps only if each persona call fits 120 s by itself, and the harness cannot separate service time from queue wait.
- Estimate (arithmetic from qwen ko numbers, not measured): input 9,065 tokens / 175.23 tok/s = about 52 s prefill per call, plus about 2,386 output tokens / 25.33 tok/s = about 94 s per persona if output splits evenly. Total about 146 s per persona, which still exceeds 120 s. A persona split alone does not clear the limit for qwen. Output shrinkage, lower effort, or a shorter per-persona schema is also needed. The 9,543 output tokens may include hidden reasoning; the record does not separate it (qwen3.8-27b-ko.md review, and summary.md:150 notes hidden reasoning is an estimate).
- Concurrency cap: src/ai/run.ts:23 sets MAX_RUNNING_RUNS = 3, and src/ai/run.ts:89 and :224 throw CONFLICT when running runs reach it. Four parallel persona calls exceed 3, so some may fail depending on insert timing (race, not verified by running).
- Persona subset already exists: src/server/ai-features.ts:58-61 takes personaIds?, and :101 selectPersonas. A per-persona call can reuse it, but the reader step writes one reader/NN.json and one runId per chapter (eval/novel/steps/chapter.ts:361-372). Merge semantics and listReaderSimRuns grouping (not read in full) are open.
- Timeout semantics in the eval: the product default for reader-sim is 120 s (src/ai/tasks/reader-sim.ts:53-61 sets no timeoutMs; src/ai/run.ts:28 DEFAULT_AI_TIMEOUT_MS = 120_000; eval/novel/eval-client.ts:109-117 and :440 use the fallback). Local runs actually abort at 3,600,000 ms (eval/novel/models.ts:35, :93 override via run.ts:93). So 120 s is only a recorded flag in the eval, not a real abort.
- Quote filter is silent: src/ai/tasks/reader-sim.ts:93-104 drops quotes that locateQuote misses and clamps rating. The eval call record stores the parsed object before this filter (eval/novel/eval-client.ts:372, :493; luna-6-en.md:143 shows the dropped quotes exist in calls but not in reader/01.json), so the dropped count should be recoverable by diffing calls/ against reader/NN.json. Not verified by running.
- Metrics gap: eval/novel/metrics.ts:1-89 exports only chapterMetrics (T3-T7). No reader metric exists. Summary counts come from finish.ts:113 (wouldTimeOut count) and byTask counts at finish.ts ~60-100. Per-call max and persona count are not summarized.
