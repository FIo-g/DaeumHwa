## Goal

Three small changes to the reader simulation (`reader-sim` task, `runReaderSimulation`):

1. A cloud provider gets a 270,000 ms limit for the one call that carries all four personas (today the 120,000 ms default applies and the product would have timed out on a call that really took 231 s).
2. A persona moment whose quote differs from the manuscript only in letter case or in spacing is kept, and is stored with the manuscript's own wording. Today it is dropped.
3. A system-prompt rule: say only what `<previous_summaries>` states about earlier chapters; when it says `(없음)`, do not claim to have read earlier chapters or seen the same wording in them.

Plus one honest-label change in the eval harness: the cloud `reader-sim` call record must show the limit the product now uses (`productTimeoutMs`), so `wouldTimeOut` stays true to the product.

## Gating (what is local-only, what changes the cloud default, on purpose)

- Time limit: cloud branch only, `!isLocalProvider(aiClient.provider)`, via `meta.timeoutMs`. The local branch (`runAiTaskSplit`, 120 s per persona) is untouched. In eval the override (`setAiTimeoutOverride`, cloud 900,000) still wins, so R2b aborts nothing differently; only the stored `productTimeoutMs` and `wouldTimeOut` change.
- Quote check and the system rule apply to every provider (spec row P7 is "app", not "app-local"). They are intended changes of the cloud default path. No option, flag or env switch. The local split calls use the same `postProcess` and the same system text.
- Not touched: the `reader` eval step, the eval config, run folders, `bible.json`, `author.md`, speech and two-step options (M5).

## Risks

- A 270 s wait is long in the UI. It only applies to a call that is already slow; the typical cloud call is 24-39 s. The limit leaves 30 s under the route's `maxDuration`; a hung provider call occupies a serverless function for up to 270 s.
- The spacing-insensitive match drops ALL whitespace on both sides, so it can accept a quote whose words are the manuscript's but split differently. The stored text is the manuscript's own slice, so what the author sees is true.
- Case folding with `toLowerCase()` can change string length; the index map handles it (test with `İ`). Do not use `locale` variants.
- The rule may make a persona less "binge-like" in later chapters. It still allows what `<previous_summaries>` states (up to 3 summaries). The R2b check is the count of invented earlier-chapter claims in the reviews; the cloud base rate in the saved runs is about 0, so a flat result is expected and not a failure.
- The English fixture and the pinned Korean test are the two places that break if the new line differs by one character from the line in the brief. Copy both lines exactly.
- qwen ko quotes joined with ` / ` (several paragraphs in one quote) are still dropped. Out of scope (local, not in the spec).
- Cross-track: P4 edits another key of the same fixture JSON (sequential, different keys; use the python snippet so other keys stay byte-identical). M2 and M4 edit `eval-client.ts` `prepare()`/`CallRecord` earlier; P7 changes only the `taskTimeout` line. If P14 gives `locateQuote` a Korean word-boundary check, the loose fallback here would accept an unbounded match again; that keeps today's reader-sim behaviour and needs no change. The R2 summary writer must note that cloud `reader-sim` `productTimeoutMs` is 120,000 in R2a and 270,000 in R2b.
