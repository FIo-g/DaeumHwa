## Goal

Two opt-in options on `eval:novel init`, stored in the run config, so the compare runs R2s and R2t (spec 2, 6) can be made on the same code as R2b. The default of both is today's behaviour, byte for byte.

1. `--speech on`: the run turns the product's speech feature on (`AI_SPEECH_STYLE=on` while the run is open), and uses a copy of the story bible whose answer bank carries each character's `voice`. The copy is written to `<run dir>/bible.json` when the run is created. The author instructions (`eval/novel/agents/author.md`) tell the author to read `<dir>/bible.json` when it exists. The fixtures `eval/fixtures/novel/<lang>/bible.json` are not changed (user decision, spec 3).
2. `--two-step on`: the draft step passes `twoStep: true` to `startDraft` (a `draft-beats` call before the prose) and the continuity step runs the scene rewrite, also on a cloud profile. Local profiles already do both; they refuse the option because it would change nothing.

Measured later (not by this track): R2s = Haiku ko + Luna ko with `--speech on` (date folder `2026-10-19-r2speech`); R2t = Haiku ko + Luna ko with `--two-step on` (`2026-10-19-r2twostep`). Both run on the R2b code.

   ```ts
   export const RUN_BIBLE_FILE = 'bible.json'
   const SPEECH_LABEL = { ko: '말투', en: 'speech' } as const

   /** Copy of the bible whose answer bank also carries each character's voice. The input is not changed. */
   export function withVoicesInAnswerBank(bible: Bible): Bible {
     const extra = new Map<string, string[]>() // bank key -> lines, in character order
     for (const character of bible.characters) {
       const voice = character.voice.trim()
       if (voice === '') continue
       const entry =
         bible.answerBank.find((item) => item.topics.includes(character.name)) ??
         bible.answerBank.find((item) => character.aliases.some((a) => item.topics.includes(a)))
       if (!entry) throw new Error(`answer bank has no entry for character ${character.key}`)
       const line = `${character.name} ${SPEECH_LABEL[bible.lang]}: ${voice}`
       extra.set(entry.key, [...(extra.get(entry.key) ?? []), line])
     }
     return {
       ...bible,
       answerBank: bible.answerBank.map((item) => {
         const lines = extra.get(item.key)
         return lines ? { ...item, answer: `${item.answer} ${lines.join(' ')}` } : item
       }),
     }
   }
   ```

## Gating (how the options stay out of the default path)

- Both options live only in `RunConfig`, are written only when given, and are read only in `openRun` (speech) and `chapter.ts` `twoStepOn` (two-step). No config key means exactly today's behaviour: `AI_SPEECH_STYLE` forced to `''`, fixtures read, `twoStep` only for `queue === 'local'`.
- `twoStepEnabled` is the single place that decides; local profiles are `true` regardless of the option, so local runs (and every existing local test) are unchanged. Cloud and `fake` profiles are `true` only with the option, so `run.D.test.ts`'s cloud case stays green.
- The foreign-script repair stays on `isLocalProfile` (local only). `isLocalProvider(client.provider)` inside the product (split extraction, concurrency) is untouched, so a cloud profile with `--two-step on` keeps the cloud extraction path.
- `src/**` is not edited: no product behaviour changes. The speech feature itself is the existing track B code.
- The fixtures and the author guide are not edited; the copy is derived from the fixture at run creation.
- An existing run resumes through the workflow's flagless `init` (the rule F4 set), so R2s and R2t runs are created by hand first and the workflow then only continues them.

## Risks

- Two tracks edit the same lines. M4 adds `--product-limits` to the same `RunConfig`, `RunCreateOptions`, `createRun`, `InitOptions`, `initRun` and `dispatch`; M3 and others edit the README; M6 edits `author.md` and the workflow. Work in the planned order and add beside, never over, what an earlier track left. M6 must keep the two `<dir>/bible.json` lines in `author.md` (the static test in `bible.r2.test.ts` catches a loss).
- An author agent that ignores the run copy makes a speech run measure an incomplete bank without any error. Guards: the `author.md` lines, the static test, and the README check on `author-decisions.jsonl`. A run that fails the check is discarded, not scored.
- A speech run changes more than the prompts: the interview answers (and so the wiki) change because the bank is richer. R2s versus R2b measures the whole feature with its enriched bank (as the spec intends); the result document should say so.
- Cloud two-step adds one `draft-beats` call and up to two `scene-rewrite` calls per chapter, and the beat call counts against the product's 290 s draft budget (see Evidence: 70-116 s drafts leave room). If a future slow model passes 260 s elapsed, the continuation is skipped silently; the run's `draft-chapter` and `draft-continue` call records show it.
- P1, P2 and P3 (beat scene count, decision state, beat locations to the continuity check) change what `--two-step on` runs on the R2b code. Cross-check result: P1 and P2 ride on `twoStep` (they only act when a beat list exists), and P3 was corrected to gate on `twoStepOn(ctx)` plus an existing `beats.json`, so R2t sees all three. `twoStepOn` must therefore stay a function of `chapter.ts` that the `check` step can call. P9 (retry budget) is local-eval only by the spec and does not apply to cloud runs; that is intended.
- `bible.json` in a run dir is inside `eval/results` (gitignored, linked into the R2b work tree); nothing publishes it. `writeBlindCopy` does not copy it.

## Open questions (default taken)

- Accepted values: only `on`. `off` is rejected (`unknown speech value: off`), because `--two-step off` could not turn the local default off and a second spelling of "default" invites mislabeled runs. Omit the flag for the default.
- `--two-step on` on a local profile: refused with a message, like F4 refuses `--helper-think` where it changes nothing. `--speech on` on a local profile is allowed (it changes the prompts).
- Foreign-script repair (track C) with `--two-step on` on cloud: not enabled. The spec names only the draft split and the scene rewrite.
- Where the voices go: appended to the answer of the bank entry that lists the character's name in `topics` (aliases as a fallback), in the form `<name> 말투: <voice>` (en: `<name> speech: <voice>`). The `minor` entry carries two characters. The spec says "해당 인물 답" without a format.
- How the options reach a run: `init` flags only; the workflow (M6's file) gets no new args. R2s and R2t runs are created by hand with `--dir`, as the README already says for `--helper-think`.
- The docs review header (`모델: ... | 언어: ...`) and `run-summary.json` do not record the options; the date folder names (`r2speech`, `r2twostep`) and `config.json` do. Add them only if the summary step needs them.
- `resummarize` reads the fixture bible, not the run copy (nothing it uses differs).
- Test file names carry the `m5` tag where another track tests the same source file (`models`, `cli`, `run`); `bible.r2.test.ts` is M5's alone.
