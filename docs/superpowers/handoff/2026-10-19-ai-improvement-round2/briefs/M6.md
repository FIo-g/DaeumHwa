   ```js
   // The checkout the eval runs in when args.repo is not given.
   const DEFAULT_REPO = '/Users/taehyeong/Documents/GitHub/DaeumHwa'

   // The checkout root for every command and agent input. args.repo may name another checkout, such as
   // a worktree. The value goes into shell commands that runner agents execute, so only plain path
   // characters are accepted; this script has no Node API, so the check is a regex.
   function resolveRepo(raw) {
     if (raw === undefined || raw === null) return DEFAULT_REPO
     const bad =
       'args.repo must be an absolute path made of letters, digits, _ . - and / (no spaces, no ..)'
     if (typeof raw !== 'string') throw new Error(bad)
     const repo = raw.replace(/\/+$/, '')
     if (!/^\/[\w./-]+$/.test(repo) || /(^|\/)\.\.(\/|$)/.test(repo)) throw new Error(bad)
     return repo
   }
   ```

   ```js
   const date = args.date
   ```

```ts
  ...params: string[]

/** Replies of the stub agent. `advance` is consumed by successive `pnpm eval:novel advance` commands. */
function reply(prompt: string, advance: StepReply[]): unknown {
  if (prompt.startsWith('Follow the instructions in')) return 'ok' // author, reviewer, resume-note, summary
  if (prompt.includes('eval:novel advance')) return advance.shift() ?? { status: 'done', detail: '{}' }
  if (prompt.includes('test -f')) return { status: 'exists', detail: '' }

}

/** Runs the workflow text offline. Returns the prompts of every agent call, the logs and the result. */
async function runWorkflow(args: Record<string, unknown>, advance: StepReply[] = []) {
  const prompts: string[] = []
  const logs: string[] = []
  const queue = [...advance]
  const agent = async (prompt: string) => {
    prompts.push(prompt)
    return reply(prompt, queue)
  }
  const parallel = (thunks: Array<() => Promise<unknown>>) => Promise.all(thunks.map((t) => t()))
  const body = source.replace('export const meta =', 'const meta =')
  const run = new AsyncFunction('args', 'log', 'phase', 'parallel', 'agent', body)
  const result = await run(args, (m: string) => void logs.push(m), () => {}, parallel, agent)
  return { prompts, logs, result }
}

/** The directory after `cd` in every runner command. */
function cdRoots(prompts: string[]): string[] {
  return prompts.flatMap((p) => [...p.matchAll(/cd (\S+) &&/g)].map((m) => m[1] as string))
```

## Gating

- This is harness-only. The gate is `args.repo`: absent or `null` gives `DEFAULT_REPO`, which is the old constant, so every runner prompt is byte-identical to today's (`cd <default> && pnpm eval:novel ...`, the `reviewerPrompt`, the copy prompts). The "falls back to the default repo" test pins the advance command text.
- Prompts that change in the default case: the author, resume-note and summary agent prompts gain `root = <default>`, and the summary agent's "Also read" line becomes absolute. The agent docs fall back to the old behaviour when `root` is missing, so an older workflow script resumed against the new docs still works.
- Local versus cloud: nothing here depends on the provider or on `queue === 'local'`. The product cloud path (`src/`) is not touched, so the spec's rule that the cloud default path stays as is holds.
- A resumed workflow (`resumeFromRunId`) started before this track misses the cache only for author, resume and summary calls (their prompts changed); runner calls are unchanged.

## Risks

- Shell injection through `args.repo`: runner agents execute `cd ${REPO} && ...`. The strict character set above is the guard; do not loosen it to allow spaces or `~`.
- The docs copies of reviews and the summary land in `<repo>/docs/eval/novel/<date>/`. When `repo` is a worktree, they are in the worktree, not in the main checkout (spec section 5 step 7 commits from the main checkout). The orchestrator copies those files over. Not solved here (see Open questions); the README bullet says so.
- `eval/novel/agents/*.md` are read by agents at call time. Applying this change in a checkout that a live workflow reads from changes that run's instructions mid-run. Apply it only in the implementation work tree (spec sections 4 and 5), not in a checkout a running eval uses.
- A worktree without `node_modules`, `.env.local` or the `eval/results` link makes `pnpm eval:novel` fail or write results into the worktree. The runner reports the error and the run ends as `error`. README documents the setup; the workflow does not check it.
- The offline test executes the workflow text through the `AsyncFunction` constructor. If ESLint reports `no-new-func` or `@typescript-eslint/no-implied-eval` for it, add a single `// eslint-disable-next-line <rule>` above that line; the file is a test.
- M3 and M5 edit the same workflow and md files. Stay with the anchors named above and keep their additions.

## Open questions (default chosen)

1. One root or two (the round-1 baseline fork used `RESULTS_REPO` for run folders)? Default: one `args.repo`. With the `eval/results` link the run folders are the same, and `dir` stays lexically inside `root` as `author.md` requires. The spec asks for one `args.repo`.
2. Should the docs copies go to the main checkout when `repo` is a worktree? Default: no new argument. `publish.ts` and `publish-review` are bound to their cwd root, and changing them is outside M6. The README tells the orchestrator to move the files.
3. Should `reviewer.md` get a `root`? Default: no. The reviewer reads only the blinded copy (`reference/` holds the criteria) and "reads nothing outside dir"; a root input would invite exploration. It has no absolute path, so nothing to remove. The static test asserts it has no `root`.
