4. `eval/novel/thresholds.ts`, pure parts first, each with its test written first:
   - `loadRunEvidence(dir)`: read-only. `config.json` -> `lang` (must be ko or en, else throw naming the folder); `chapters/` files matching `/^\d{2}\.md$/`, sorted, text trimmed; `wiki-final.json` parsed with a tolerant zod schema (unknown keys dropped, missing arrays default to empty; archived entries, facts and style cards skipped, `examples` that are empty skipped); `calls/*-continuity-check.json` with `task === 'continuity-check'`, `error == null` and a prompt holding `<wiki>` and `</wiki>`, sorted by file name, giving `wikiChars` = length from the start of `<wiki>` to the end of `</wiki>` and `cardsInPack` = number of lines starting with `[E<digits>] ` inside it; `exempt = bibleExempt(loadBible(lang))`.    - `dupSweep(runs, labels, values, current)`: per run and per card, every unordered pair of its facts.      change: `${value}로 바꾼다: 맞힌 라벨 ${base.caught}개 → ${best.caught}개, 잘못 표시 ${base.wrong} → ${best.wrong}, 라벨 없는 표시 ${base.unlabeled} → ${best.unlabeled}.`

## Gating

- The replay is an eval-only developer tool. Nothing in `src/` imports `eval/`. It reads saved run folders and writes only to the `--out` file under `docs/`.
- `isNearDuplicateFact`'s new third parameter defaults to `FACT_DUPLICATE_DICE`, so the three product call sites (`extractionToProposals` twice, `runChapterCheck` race check) behave exactly as before in commits 1 and 2.
- The only product behaviour change is `FACT_DUPLICATE_DICE` in commit 3. It is not gated by provider or option: the near-duplicate filter is provider independent, and the spec lets M7 change a value on evidence ("process, app"). The cloud default path therefore changes by exactly this one constant and only if the rule fires.
- Cross-track timing: the R2a worktree must be created from commit 2 (or from the M6 tip, or from the P8 commit that the cross-check placed right after commit 2), not from commit 3. Commit 3 is held back and lands as the first item of the P batch, after the R2a cut. Commit 3 changes how many duplicate facts reach the author, which would mix into "R2a vs round 1" (author rejection count). R2b is cut after all P tracks, so it includes commit 3.
- P15 edits the same function (Korean numerals before the compare). It starts after commit 3 and must keep the `minDice` parameter.

## Risks

- Labels are one Sonnet reviewer's sentences per run, mapped to word/sentence/pair items by the brief author. Mapping errors bias the sweeps; the loud-failure label matching and the `source` column make them auditable. The sample is six one-chapter runs from three models; luna en supplies 3 of the 4 pairs gained at 0.7.
- Lowering the fact Dice adds English false duplicates for short sentences that differ by a negation or an antonym (no content-word check in English). A false duplicate silently drops a possibly contradicting fact (counter only, no UI). At 0.7 the delta is limited to short sentences; long ones are already affected at 0.8. Pinned as a documented limit in test 8. Mitigation (an English polarity check) is out of scope.
- G1 now passes known facts to the extractor, so fewer duplicates reach the filter than in the saved runs; the real effect of 0.7 will be smaller than 4 of 23.
- The sweeps use the final wiki as the pair universe, not the proposals the author saw. Pairs that the author rejected are not in it.
- `unlabeled` is not "wrong": nothing in the reviews says those hits are false. The rule treats an increase as a cost and a decrease as no evidence.
- Python-port numbers in Evidence/Expected can differ from the TS replay by a count in `unlabeled`. Decisions rest on `caught` gains, which are robust (repeat max gain 0, copy max gain 2, dup +4).
- A flipped pair in an existing test at 0.7 (commit 3) means the report is missing a counter-example: revert the constant and report it.
- Do not run `resummarize` on the saved folder, and do not point `--out` into `eval/results`.
