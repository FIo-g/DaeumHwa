## Goal

`findNumericFactMismatches` (`src/ai/numeric-facts.ts`) compares a manuscript sentence with a confirmed wiki fact, in code, so an empty model answer cannot hide the mismatch. Today it compares one thing: `N살` against a fact that contains `나이`. After this track it compares four kinds, with the same narrow style (skip when in doubt):

| Kind | Read from Korean | Read from English |
|---|---|---|
| `age` | `N살` (unchanged) | `N years old`, `aged N` (N is digits or an English number word 0-99) |
| `year` | `NNN년`, `NNNN년` (an absolute year) | `in [the year] NNNN`, `year NNNN` |
| `floor` | `N층짜리`, `N층 높이`, `N층 규모`, `N층으로 솟/이루어/지어/되어/된`, `모두/전부/총/통틀어 N층` | `N-story`, `N stories/storeys/floors/levels tall/high`, `rose/rises/towered/towers N stories/storeys/floors` |
| `person` | `모두/전부/총/통틀어 N명`, `N명뿐`, `N명밖에` | `all/only/exactly/just/a total of/total of N people/persons/men/women/members/soldiers/guards` |

A hit is a `contradiction` / `medium` issue, exactly as for ages today (`numericIssues` in `continuity-check.ts` already maps every hit; it needs no code change). No prompt, schema, UI or Korean product copy changes. The new fixture and doc are data for the R2c measurement; the measurement itself is run by the orchestrator, not by this track.

## Design (TDD order; find code by symbol name)

Rules for the whole track (read first):
- Same style as today: when in doubt, skip. A sentence gives at most one hit. Nothing here throws.
- Every number pattern has exactly two capturing groups: group 1 is the text of the match before the number (written `()` when empty), group 2 is the number token. Offsets come from `match.index` and `match[1].length`.
- Regexes used with `.test()` must not carry the `g` flag (it keeps `lastIndex` between calls). Patterns used with `matchAll` must carry it; `matchAll` clones the regex, so module-level constants are safe.
- English number words are read for 0 to 99 only (`sixteen`, `Twenty-seven`, `twenty seven`). Korean number words (스물일곱, 열한, 구층) are not read. A hyphenated adjective (`five-year-old`) is not read: it usually describes someone else.
- Count and year forms are closed lists on purpose. A bare `5층` is a position ("5층에서"), a bare `3명` is part of a group ("3명을 보냈다"), and a two-digit `12년` is a duration. They are not totals.

```ts
// Number readers for the numeric fact check (P13). Pure: no DB, no AI, no imports.
// Reads one kind of quantity from a text: an age ("27살", "twenty-seven years old"), an absolute
// year ("312년", "built in 1204"), a floor count ("12층 높이", "nine-story") or a headcount
// ("모두 7명", "only twelve guards"). Digits and English number words 0-99 are read; Korean number
// words (스물일곱, 열한) are not. The count and year forms are narrow on purpose: a floor in a
// sentence ("5층에서") or a part of a group ("3명을 보냈다") is not a total.

export type QuantityKind = 'age' | 'year' | 'floor' | 'person'

export const QUANTITY_KINDS: readonly QuantityKind[] = ['age', 'year', 'floor', 'person']

/** Korean label and counter used in the hit explanation ("위키의 층수(12층)와 ..."). */
export const QUANTITY_LABEL: Record<QuantityKind, { label: string; unit: string }> = {
  age: { label: '나이', unit: '살' },
  year: { label: '연도', unit: '년' },
  floor: { label: '층수', unit: '층' },
  person: { label: '인원', unit: '명' },
}

export type Quantity = {
  kind: QuantityKind
  value: number
  /** The number as written: "27", "twenty-seven". */
  token: string
  /** Offsets of the number token in the text (end exclusive). */
  tokenStart: number
  tokenEnd: number
  /** Offsets of the whole matched expression ("27살", "nine-story", "모두 7명"). */
  start: number
  end: number
  /** False only for the Korean "N살" age form, which keeps the rule it had before P13. */
  needsSubject: boolean
}

const EN_ONES = [
  'zero', 'one', 'two', 'three', 'four', 'five', 'six', 'seven', 'eight', 'nine', 'ten',
  'eleven', 'twelve', 'thirteen', 'fourteen', 'fifteen', 'sixteen', 'seventeen', 'eighteen', 'nineteen',
]
const EN_TENS = new Map<string, number>([
  ['twenty', 20], ['thirty', 30], ['forty', 40], ['fifty', 50],
  ['sixty', 60], ['seventy', 70], ['eighty', 80], ['ninety', 90],
])

/** English number word or 1-3 digits to a number: sixteen, Twenty-seven, "twenty seven", 7. Else null. */
export function parseEnglishNumber(raw: string): number | null {
  const text = raw.trim().toLowerCase()
  if (/^\d{1,3}$/.test(text)) return Number(text)
  const parts = text.split(/[-\s]+/)
  if (parts.length === 1) {
    const ones = EN_ONES.indexOf(parts[0])
    return ones !== -1 ? ones : (EN_TENS.get(parts[0]) ?? null)
  }
  if (parts.length === 2) {
    const tens = EN_TENS.get(parts[0])
    const ones = EN_ONES.indexOf(parts[1])
    if (tens !== undefined && ones >= 1 && ones <= 9) return tens + ones
  }
  return null
}

// 1-3 digits or an English number word 0-99. Teens come before the units so "sixteen" is not "six".
const EN_NUM =
  '(?:\\d{1,3}|(?:twenty|thirty|forty|fifty|sixty|seventy|eighty|ninety)(?:[-\\s](?:one|two|three|four|five|six|seven|eight|nine))?' +
  '|nineteen|eighteen|seventeen|sixteen|fifteen|fourteen|thirteen|twelve|eleven|ten|nine|eight|seven|six|five|four|three|two|one|zero)'
const en = (source: string) => new RegExp(source, 'gi')

type Pattern = { re: RegExp; needsSubject: boolean }
const subjectPattern = (re: RegExp): Pattern => ({ re, needsSubject: true })

// Every pattern has exactly two capturing groups and no others: group 1 is the text of the match
// before the number (often empty, written `()`), group 2 is the number token. Do not use the `d`
// flag or named groups (tsconfig target is ES2017). Every pattern is global (matchAll).
const PATTERNS: Record<QuantityKind, Pattern[]> = {
  age: [
    { re: /()(\d{1,3})\s*살/g, needsSubject: false },
    subjectPattern(en(`\\b()(${EN_NUM})\\s+years?\\s+old\\b`)),
    subjectPattern(en(`\\b(aged\\s+)(${EN_NUM})\\b`)),
  ],
  year: [
    // 3-4 digits only (a two-digit "12년" is a duration), not "413년 동안", "413년 만에", "1990년대".
    subjectPattern(
      /()(\d{3,4})\s*년(?!대)(?!\s*(?:전|뒤|후|간|동안|째|만에|쯤|가량|이상|이하|된|묵은|넘))/g,
    ),
    subjectPattern(
      en(
        '\\b(in\\s+(?:the\\s+year\\s+)?)(\\d{3,4})\\b(?!\\s*(?:years?|days?|months?|weeks?|miles?|paces?|steps?|men|people|soldiers|coins|times)\\b)',
      ),
    ),
    subjectPattern(en('\\b(year\\s+)(\\d{3,4})\\b')),
  ],
  floor: [
    subjectPattern(/()(\d{1,3})\s*층(?:짜리|\s*높이|\s*규모|으로\s*(?:솟|이루어|지어|되어|된))/g),
    subjectPattern(/((?:모두|전부|총|통틀어)\s*)(\d{1,3})\s*층/g),
    subjectPattern(en(`\\b()(${EN_NUM})-stor(?:y|ey)\\b`)),
    subjectPattern(en(`\\b()(${EN_NUM})\\s+(?:stories|storeys|floors|levels)\\s+(?:tall|high)\\b`)),
    subjectPattern(
      en(`\\b((?:rose|rises|towered|towers)\\s+)(${EN_NUM})\\s+(?:stories|storeys|floors)\\b`),
    ),
  ],
  person: [
    subjectPattern(/((?:모두|전부|총|통틀어)\s*)(\d{1,3})\s*명/g),
    subjectPattern(/()(\d{1,3})\s*명(?:뿐|밖에)/g),
    subjectPattern(
      en(
        `\\b((?:all|only|exactly|just|a\\s+total\\s+of|total\\s+of)\\s+)(${EN_NUM})\\s+(?:people|persons|men|women|members|soldiers|guards)\\b`,
      ),
    ),
  ],
}

/**
 * Every quantity of one kind in a text, in text order. Two patterns that read the same number
 * ("모두 12층짜리") give one quantity (the longer match). A token that is not a number is dropped.
 */
export function readQuantities(text: string, kind: QuantityKind): Quantity[] {
  const byToken = new Map<number, Quantity>()
  for (const { re, needsSubject } of PATTERNS[kind]) {
    for (const match of text.matchAll(re)) {
      const token = match[2]
      const value = /^\d+$/.test(token) ? Number(token) : parseEnglishNumber(token)
      if (value === null) continue
      const start = match.index ?? 0
      const tokenStart = start + match[1].length
      const quantity: Quantity = {
        kind,
        value,
        token,
        tokenStart,
        tokenEnd: tokenStart + token.length,
        start,
        end: start + match[0].length,
        needsSubject,
      }
      const same = byToken.get(tokenStart)
      if (!same || quantity.end > same.end) byToken.set(tokenStart, quantity)
    }
  }
  return [...byToken.values()].sort((a, b) => a.start - b.start)
}

// Words that name what happened in a year. A year is compared only when the wiki fact and the
// manuscript sentence share one of them, so "건국 412년" is never compared with "멸망 590년".
const YEAR_EVENTS_KO = ['태어', '출생', '죽', '사망', '건국', '창건', '세워', '설립', '멸망', '무너', '즉위', '완공', '지어']
const YEAR_EVENTS_EN = ['born', 'died', 'founded', 'built', 'fell', 'destroyed', 'collapsed', 'crowned', 'established']
const YEAR_EVENTS_EN_RE = YEAR_EVENTS_EN.map((word) => ({ word, re: new RegExp(`\\b${word}\\b`, 'i') }))

/** The year-event words found in a text. */
export function eventWords(text: string): Set<string> {
  const found = new Set<string>()
  for (const word of YEAR_EVENTS_KO) if (text.includes(word)) found.add(word)
  for (const { word, re } of YEAR_EVENTS_EN_RE) if (re.test(text)) found.add(word)
  return found
}
```

Behaviour that must stay exactly as it is for the Korean `N살` age (the 13 existing test entries pin it): the `TIME_FRAME` list, the `보다` skip, the relative-after list, the `나이` gate for a Korean age fact, the one-value-per-entry rule, the possessive skip, the suggestion `sentence with N살 replaced by the wiki age`, and the explanation text `위키의 나이(27살)와 원고의 나이(25살)가 다릅니다.`. What is new:
- Four kinds, looped in the order `age, year, floor, person`; a sentence gives at most one hit.
- `이었|였던` is a skip word for an age only (it was in the old shared list); a year or a count is often written in the past tense ("413년에 건국되었다", "모두 9명이었다").
- English skip words (`EN_TIME_FRAME`, `than`) and an approximate word right before the number (`about twenty years old`).
- A Latin name must not sit inside a longer word (`Serinity` is not `Serin`); a name followed by `'s` is a possessive.
- Every pattern except the Korean `N살` also needs the entry to be the subject of the sentence (`isSubject`: the entry name sits before the number and is followed by 은/는/이/가, or by an English verb such as is/was/had/kept/rose). This is what keeps "등대 옆에는 5층 높이의 창고가 있었다" and "Mara Voss carried a girl, twenty years old" quiet.
- A year is compared only when the wiki fact and the sentence share a year-event word (건국, 멸망, built, fell ...). A fact with a year but no event word is ignored.
- The suggestion replaces the manuscript number token with the wiki's own token ("27" -> "27살" as before; "sixteen" stays "sixteen"), so it is the sentence with one number swapped.

```ts
import type { ContextPack, PackEntry } from '@/ai/context'
import { splitSentences } from '@/lib/korean/sentences'
import {
  eventWords,
  QUANTITY_KINDS,
  QUANTITY_LABEL,
  readQuantities,
  type QuantityKind,
} from '@/ai/numeric-quantities'

// Numeric fact check (H, widened by P13): finds a sentence whose number contradicts the one in a
// confirmed wiki fact about the same card. Four kinds are read (see numeric-quantities.ts): age
// ("N살", "N years old"), absolute year, floor count and headcount.
// Runs in code, not in the model, so an empty model answer cannot hide it. It is deliberately
// narrow: a sentence with a flashback or time skip word, two numbers of the kind, two named
// entries or a possessive ("세린의 동생은 9살이다") is skipped. So is a relative or rough number
// ("5살 어린 동생", "5살짜리", "about twenty years old", "동생보다 5살 많다"). Only a number in a
// confirmed fact is compared, and only when the entry has exactly one such number. Year, floor,
// headcount and the English age forms also need the entry to be the subject of the sentence;
// a year also needs a shared event word (건국, built). Korean number words (스물일곱) are not read.

export type NumericFactHit = {
  kind: QuantityKind
  factRef: string
  entryRef: string
  wikiValue: number
  foundValue: number
  quote: string
  start: number
  end: number
  wikiExcerpt: string
  explanation: string
  suggestion: string
}

// Words in a manuscript sentence that put the number in another time or make it relative.
const TIME_FRAME = /(때|시절|무렵|전에|예전|과거|년 전|년 뒤|년 후|이후|뒤에|후에|나중)/
// Past-state words: only an age skips on them ("25살이었다"); a year or a count is often past tense.
const AGE_PAST_FRAME = /(이었|였던)/
const EN_TIME_FRAME =
  /\b(?:when|while|ago|later|before|after|since|until|once|formerly|used to|back then|by then|then|that year|next year|last year|at the age of)\b/i
// Words right after a number that make it a relative age or a rough guess ("5살 어린 동생",
// "20살이 넘은", "5살짜리"), not the number of the named entry.
const RELATIVE_AFTER_NUMBER =
  /^\s*(?:더\s*)?(어리|어린|어려|많|위|아래|차이|터울|연상|연하|배기|짜리|남짓|쯤|정도|이 넘|가 넘)/
const EN_APPROX_BEFORE =
  /\b(?:about|around|nearly|almost|roughly|approximately|some|over|under|maybe|perhaps|barely)\s+$/i
const EN_SUBJECT_VERB =
  /^\s+(?:is|was|are|were|has|had|stood|stands|rose|rises|towered|towers|kept|keeps|numbered|held|holds)\b/i
// An English age fact reads "X is sixteen years old" or "X, age 16"; it must not be about a time.
const EN_AGE_FACT = /\b(?:age|aged|is|are)\b/i

/** Names and aliases that can identify an entry in a sentence (at least 2 characters). */
function namesOf(entry: PackEntry): string[] {
  return [entry.name, ...entry.aliases]
    .map((name) => name.trim())
    .filter((name) => Array.from(name).length >= 2)
}

const LATIN_NAME = /^[A-Za-z][A-Za-z '’.-]*$/
const escapeRegExp = (text: string) => text.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')

/** True when the name occurs in the text. A Latin name must not sit inside a longer word. */
function mentions(text: string, name: string): boolean {
  if (!LATIN_NAME.test(name)) return text.includes(name)
  return new RegExp(`(?<![A-Za-z])${escapeRegExp(name)}(?![A-Za-z])`).test(text)
}

type WikiQuantity = {
  value: number
  /** The number as the fact wrote it ("27", "sixteen"); the suggestion uses it. */
  token: string
  factRef: string
  excerpt: string
  /** Year-event words of the fact(s) that state this year. Empty for the other kinds. */
  events: Set<string>
}

/** A Korean age fact says "나이"; an English one says "is ... years old" or "age". */
function isAgeFact(content: string): boolean {
  return content.includes('나이') || (EN_AGE_FACT.test(content) && !EN_TIME_FRAME.test(content))
}

/**
 * The single confirmed number of one kind for an entry: from confirmed facts that state exactly
 * one number of the kind (an age fact must pass `isAgeFact`, a year fact must hold a year-event
 * word). Two different numbers make the entry unusable for this kind (the wiki is itself unclear).
 */
function wikiQuantity(entry: PackEntry, kind: QuantityKind): WikiQuantity | null {
  const byValue = new Map<number, WikiQuantity>()
  for (const fact of entry.facts) {
    if (fact.status !== 'confirmed') continue
    if (kind === 'age' && !isAgeFact(fact.content)) continue
    const found = readQuantities(fact.content, kind)
    if (found.length !== 1) continue
    const events = kind === 'year' ? eventWords(fact.content) : new Set<string>()
    if (kind === 'year' && events.size === 0) continue
    const [quantity] = found
    const same = byValue.get(quantity.value)
    if (same) {
      for (const word of events) same.events.add(word)
      continue
    }
    byValue.set(quantity.value, {
      value: quantity.value,
      token: quantity.token,
      factRef: fact.ref,
      excerpt: fact.content,
      events,
    })
  }
  if (byValue.size !== 1) return null
  return [...byValue.values()][0]
}

/** A name directly followed by 의 or 's marks a possessive ("세린의 동생", "Serin's brother"). */
function isPossessive(text: string, names: string[]): boolean {
  for (const name of names) {
    for (let idx = text.indexOf(name); idx !== -1; idx = text.indexOf(name, idx + 1)) {
      const rest = text.slice(idx + name.length)
      if (rest.startsWith('의') || /^['’]s\b/.test(rest)) return true
    }
  }
  return false
}

/** True when a name before `before` is followed by a subject particle (은 는 이 가) or an English verb. */
function isSubject(text: string, names: string[], before: number): boolean {
  for (const name of names) {
    for (let idx = text.indexOf(name); idx !== -1; idx = text.indexOf(name, idx + 1)) {
      const end = idx + name.length
      if (end > before) continue
      const rest = text.slice(end)
      if (/^[은는이가]/.test(rest) || EN_SUBJECT_VERB.test(rest)) return true
    }
  }
  return false
}

/**
 * Compares each sentence that is about exactly one pack entry (and has exactly one number of a
 * kind) with that entry's confirmed number of the same kind. A mismatch becomes a hit; a sentence
 * gives at most one hit. Never throws: empty input gives no hits.
 */
export function findNumericFactMismatches(input: {
  chapterText: string
  pack: ContextPack
}): NumericFactHit[] {
  const entries = input.pack.entries
  const wikiCache = new Map<string, WikiQuantity | null>()
  const wikiOf = (entry: PackEntry, kind: QuantityKind) => {
    const key = `${entry.ref}:${kind}`
    if (!wikiCache.has(key)) wikiCache.set(key, wikiQuantity(entry, kind))
    return wikiCache.get(key) ?? null
  }
  const hits: NumericFactHit[] = []

  for (const sentence of splitSentences(input.chapterText)) {
    const text = sentence.text
    if (TIME_FRAME.test(text) || EN_TIME_FRAME.test(text)) continue
    if (text.includes('보다') || /\bthan\b/i.test(text)) continue

    for (const kind of QUANTITY_KINDS) {
      const found = readQuantities(text, kind)
      if (found.length !== 1) continue
      const [quantity] = found
      if (kind === 'age' && AGE_PAST_FRAME.test(text)) continue
      if (RELATIVE_AFTER_NUMBER.test(text.slice(quantity.end))) continue
      if (EN_APPROX_BEFORE.test(text.slice(0, quantity.start))) continue

      const named = entries.filter((entry) => namesOf(entry).some((name) => mentions(text, name)))
      if (named.length !== 1) continue
      const [entry] = named
      const wiki = wikiOf(entry, kind)
      if (!wiki) continue
      const names = namesOf(entry)
      if (isPossessive(text, names)) continue
      if (quantity.needsSubject && !isSubject(text, names, quantity.start)) continue
      if (kind === 'year' && ![...eventWords(text)].some((word) => wiki.events.has(word))) continue
      if (quantity.value === wiki.value) continue

      const { label, unit } = QUANTITY_LABEL[kind]
      hits.push({
        kind,
        factRef: wiki.factRef,
        entryRef: entry.ref,
        wikiValue: wiki.value,
        foundValue: quantity.value,
        quote: text,
        start: sentence.start,
        end: sentence.end,
        wikiExcerpt: wiki.excerpt,
        explanation: `위키의 ${label}(${wiki.value}${unit})와 원고의 ${label}(${quantity.value}${unit})가 다릅니다.`,
        suggestion: text.slice(0, quantity.tokenStart) + wiki.token + text.slice(quantity.tokenEnd),
      })
      break
    }
  }
  return hits
}
```

## Risks

- False alarms are worse than misses (the author sees a wrong "contradiction"). Hence the closed forms, the subject check, the shared event word for years, one value per entry, and skip-when-in-doubt. The saved data gives 0 hits over 20 files; the fixture gives 0 of 10 traps. The planted set is small; watch `falsePositives` and `trapHits` in R2c.
- Still possible: "The tower had 14 floors on the east side" is not read (no closed form); "등대는 5층 높이의 창고를 품고 있었다" is read as the tower's height (the entry is the subject). Accepted.
- Korean number words are invisible (Open question 1). The saved Korean runs and the Korean story bible use them for ages, so the Korean age check stays inert in eval runs.
- An entry that has a founding year and a fall year in two facts is skipped for years (two different values). Open question 3.
- Sentence splitting: `splitSentences` splits on `.`, so `Mr. Voss` or `3.5` can cut a sentence. A cut sentence has fewer words and usually fewer numbers, so it skips; no special handling.
- The planted fixture mixes languages in one work and the Korean system prompt asks for Korean output and exact quotes. A model may quote the English chapters less exactly; `locateQuote` then drops the issue. The code-made issues are exact sentences, so they always locate. Record any English-chapter model miss as such, not as a regression.
- `pnpm eval:continuity` goes through a tsx wrapper that failed in the earlier sandbox (EPERM on the IPC pipe). Fallback in the doc: `node --import tsx eval/run-continuity.ts ...`.
- One real run per arm is noisy. The deterministic code-only numbers in the doc are the stable part.
