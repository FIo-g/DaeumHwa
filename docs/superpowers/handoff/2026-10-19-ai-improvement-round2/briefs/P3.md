## Goal

When an eval run drafts in two steps (`draft-beats` first: every local profile, and a cloud profile created with M5's `--two-step on`), the saved beat list of the chosen draft is also given to the continuity check, as a short per-scene list of place, people and object locations. The check can then compare "where this scene happens and where things are" with the wiki. Nothing else changes:

- The product (route, server action) and every cloud run without `--two-step on` send the continuity prompt exactly as today.
- The model may only use the list to find wiki conflicts. A flag still needs a wiki ref, or the code drops it.

## Gating

- Product and cloud default path: unchanged by construction. `scenePlan` is optional, nothing in `src/app` or `src/server/actions` passes it, and the continuity input object and prompt are identical when it is absent (tests 1-3 of `continuity-check.r2.test.ts`, tests 2-3 of `chapter-check.r2.test.ts`, test 2 of `run.p3.r2.test.ts`). `CONTINUITY_SYSTEM` and the English systems are untouched.
- Two-step runs only: the eval `check` step passes a plan only when `twoStepOn(ctx)` (profile `queue === 'local'`, or the run config has `twoStep: true` from `--two-step on`) AND the chosen attempt's `beats.json` exists and parses. Default cloud runs (R2a, R2b, R2s, R2l) write no beats and are skipped by both tests.
- M5 interaction (cross-check correction): `--two-step on` lets a cloud profile draft in two steps and write `beats.json`. P3 follows the same switch (`twoStepOn`), like P1 and P2, so R2t measures the whole local two-step flow (beats, P1, P2, P3, scene rewrite) on a cloud model. The result document must say that R2t versus R2b mixes all of these.
- No CLI flag and no config field. The service itself does not check the provider (same as `startDraft`'s `twoStep`): the caller gates.
- No R2a/R2b cloud number can move because of this track; it has no cloud measurement. Its effect shows only in a later local run (T2 count and the continuity check's valid flags, compared with a local run from before this commit; `config.json` records the commit).

## Risks

- Unproven benefit (see Evidence). Only wiki-grounded place or object conflicts can gain. Order conflicts (qwen ko item 6) and internal inconsistencies are not helped by a location-only list; do not oversell it in the commit message.
- The plan comes from the same local model that wrote the draft, so it can carry a wrong place. The rule sentence and the drop-without-wiki-ref code keep a wrong plan from becoming a flag on its own, but it can still steer the model toward a false flag that happens to cite a real wiki line. Review the first local run's flags by hand.
- Prompt grows by about 450-600 characters on a call that already takes 21-36 minutes on qwen. Expected effect on time is small, unmeasured.
- Not comparable with earlier local continuity checks (README bullet says so).
- P2 coupling: this track reads `place`, `characters`, `objects` of a beat scene and parses stored `beats.json` with the current `DraftBeatsSchema`. ## Open questions (default chosen)

1. Include the event order (`sequence`) too? Default no: "location list" means where, and P2's added fields would otherwise leak into the check. Change only if the first local run shows order conflicts are the main miss.
2. Rule inside or outside the tag? Default outside, because of `TAG_DATA_RULE`.
3. A switch (`--scene-plan off`) for an A/B run like F4's `--helper-think`? Default no: the spec asks for none, and local runs are already limited. Compare by commit instead. If an A/B is wanted later, add it as a `RunConfig` field read in `openRun`, the way `helperThink` is.
4. Gate by profile only, by beats file only, or both? Default both, with the profile test widened to `twoStepOn` (see Gating; cross-check correction).
5. Give the scene rewrite the same plan? Out of scope. (`rewriteFlaggedScenes` already accepts `beats`, and the eval `rewriteStage` does not pass it; not touched here.)
6. Check provider inside `runChapterCheck`? Default no; keep the service free of provider logic and gate at the caller.
