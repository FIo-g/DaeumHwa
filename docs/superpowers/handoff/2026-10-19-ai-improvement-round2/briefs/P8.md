## Design (TDD: write each test first, watch it fail, then implement)

Definitions (use these words in code comments):

- Paragraph: a trimmed non-empty line of the chapter text (same as `chapterMetrics` `lines`).
- Narration paragraph: a paragraph whose first character is not in `DIALOGUE_OPENERS`.
- Opener: the first `[\p{L}\p{N}]+` token of the paragraph, lowercased; when it is Hangul only (`/^[가-힣]+$/`) it goes through `stripJosa`. A paragraph with no such token (`***`, `…`, `—`) has no opener and is not counted.
- Listed opener: an opener that starts at least `OPENER_MIN_COUNT` (4) narration paragraphs.

1. **Pure function and its tests first.** Write `eval/novel/metrics-openers.r2.test.ts` (cases under Tests), then create `eval/novel/metrics-openers.ts`:

   ```ts
   import { stripJosa } from '@/lib/korean/josa'

   // Paragraph opener metric (round 2, P8). Re-exported from metrics.ts. Measurement only: no
   // threshold, no prompt and no product code reads it. Tokenizer rules follow repeatedWords
   // (src/ai/guards/repeats.ts): letters and digits, lowercased, Hangul tokens lose their particle.

   /** An opener is listed when it starts at least this many paragraphs. Provisional, not calibrated. */
   export const OPENER_MIN_COUNT = 4
   /** At most this many openers are listed in `top`. */
   export const OPENER_TOP_LIMIT = 5

   export type ParagraphOpeners = {
     counted: number // paragraphs that have an opener word
     repeated: number // paragraphs whose opener is listed (all listed openers, not only `top`)
     top: { word: string; count: number }[] // listed openers, count desc then word asc, cut to the limit
   }

   const TOKEN = /[\p{L}\p{N}]+/u
   const HANGUL_ONLY = /^[가-힣]+$/

   /** The opener of one paragraph, or null when it has no letter or digit. */
   export function openerWord(paragraph: string): string | null {
     const match = TOKEN.exec(paragraph)
     if (!match) return null
     const word = match[0].toLowerCase()
     return HANGUL_ONLY.test(word) ? stripJosa(word) : word
   }

   export function countParagraphOpeners(
     paragraphs: readonly string[],
     opts?: { minCount?: number; limit?: number },
   ): ParagraphOpeners {
     const minCount = opts?.minCount ?? OPENER_MIN_COUNT
     const limit = opts?.limit ?? OPENER_TOP_LIMIT
     const counts = new Map<string, number>()
     let counted = 0
     for (const paragraph of paragraphs) {
       const word = openerWord(paragraph)
       if (word === null) continue
       counted++
       counts.set(word, (counts.get(word) ?? 0) + 1)
     }
     const listed = [...counts]
       .filter(([, count]) => count >= minCount)
       .map(([word, count]) => ({ word, count }))
       .sort((a, b) => b.count - a.count || (a.word < b.word ? -1 : a.word > b.word ? 1 : 0))
     return {
       counted,
       repeated: listed.reduce((sum, item) => sum + item.count, 0),
       top: listed.slice(0, limit),
     }
   }
   ```

   The function takes the list of paragraphs (strings) so the dialogue filter, which needs `DIALOGUE_OPENERS` from `metrics.ts`, stays in `metrics.ts`. Do not import from `./metrics` inside this file (it would be a cycle).

## Risks

- **The number is flat.** All six saved texts sit at 25.6% to 28.3% for their top opener. Expect R2a and R2b to look alike. Report it as description; never as a pass/fail, and do not set a threshold in this round.
- **Names dominate.** In Korean the top opener is the protagonist's name in every run, in English it is `she`, `the` or the name. `repeatedWords` exempts bible names (`bibleExempt`); P8 does not, on purpose (see Open questions).
- **`stripJosa` cuts some function words.** `그러나` becomes `그러`, `하지만` becomes `하지`, `그리하여` becomes `그리하` (verified with the real function). `그는` and `그가` stay as they are because the function keeps two characters. This changes only the label shown, the same as in `repeatedWords`. Do not add special cases.
- **English tokens.** An apostrophe ends the token (`Don't` gives `don`, `I'll` gives `i`, `Serin's` gives `serin`, which merges the possessive with the name on purpose).
- **Dialogue test is one character.** A paragraph counts as dialogue only when its first character is a quote mark in `DIALOGUE_OPENERS`. A line that starts with a dash and speech counts as narration.
- **Author and reviewer see a new key.** The author's `usable` rule does not use metrics, so author behaviour should not move. The reviewer sentence in step 7 is the only change to what a blinded reviewer reads, and it says "not a threshold". P8 lands before the R2a cut (cross-check decision), so R2a and R2b reviewers read the same sentence.
- **Parallel edits.** `reviewer.md` and the README are also edited by M tracks. A stale edit would clobber them: re-read each file just before the edit and use `Edit`, not a whole-file `Write`.

## Open questions (default chosen)

- **Count dialogue paragraphs?** Default: no. Quoted speech inflates common words (`the`, `i`) and the criticism is about narration frames.
- **Strip Korean particles?** Default: yes, as `repeatedWords` does, so `세린은`/`세린이`/`세린의` are one opener. A raw-어절 count would be smaller (`run-05-ko`: 17 for `세린은` against 20 for the stem) and lets a model hide the frame by switching the particle. The raw word can be read from the chapter text if someone needs it.
- **Exempt character names?** Default: no. The Q7 deduction that motivated this was exactly "세린은" opening 17 paragraphs. An exempt list would hide it.
- **Edit `docs/eval/novel-quality-criteria.md` (Q7) like E1 did for Q6?** Default: no. - **Threshold or listing a "flag"?** Default: none. `OPENER_MIN_COUNT` 4 only decides which words are listed (3 to 6 words per saved run); it is not calibrated and not a rule.
