## Goal

When a local (Ollama) eval call fails because its output hit the token cap or its answer did not parse, and the step runner then repeats the same call (`withModelRetry`), the repeat runs with a changed budget:

- Output hit the cap (`MAX_TOKENS_MESSAGE`): widen the output cap by 1.5 times (never past half of `numCtx`), and, for a helper task, also lower `think` one step.
- Answer did not parse (`FORMAT_MESSAGE`): for a helper task, lower `think` one step. The cap is not changed.
- The prose tasks (`PROSE_TASKS`: `draft-chapter`, `draft-continue`, `scene-rewrite`) keep the profile's `think` on every retry; only the cap can widen.

Nothing else changes: not the prompt, not the order of calls, not the number of retries (still one), not any cloud, fake or `--product-limits` run. The spec leaves "lower think OR widen" open; the table above is the choice (see Open questions). The call record says which budget was used.

## Evidence (verified 2026-10-19; python3 over `eval/results/novel/2026-10-18/run-0{1,4,5}-{ko,en}/`, code by reading)

Code facts:

- Step retry: `withModelRetry` in `eval/novel/steps/util.ts` calls `fn()`; on a failure it takes `ctx.client.takeLastFailure()`. An external failure throws `ExternalFailureError`; a `model` failure on attempt 1 counts `state.retried[label]` and loops to call `fn()` again with the same arguments; on attempt 2 it records `state.failed` and returns null. Callers: `advice`, `trimStage`, `draft` (one `startDraft` per try, covering `draft-beats`, `draft-chapter`, `draft-continue`), `check`, `proofread`/`reader` steps, `interview:ask`, `style:<name>` in `eval/novel/steps/*.ts`, and `guarded()`. `repairBestEffort`, the paragraph-trim round 2 and `recordContinueFailure` do NOT retry: they take the failure and move on.
- `EvalClient.prepare` sends `maxTokens = max(task maxTokens, profile.maxTokensFloor)` (32000 for qwen and gpt-oss, 8192 for exaone) and `thinkFor(profile, task, helperThink)` is the think the Ollama client sends (`thinkByTask` / `think`). Nothing depends on whether a call is a first try or a retry.
- The two failures come from the Ollama client: `done_reason: 'length'` throws `aiErrorWithUsage(MAX_TOKENS_MESSAGE, usage)` (`assertComplete` in `src/ai/ollama.ts`); an unparsable answer after both in-client attempts throws `aiErrorWithUsage(FORMAT_MESSAGE, usage)`. Both constants are exported from `@/ai/anthropic`. `settle` already computes `contextOverflow` (input plus output tokens at least `numCtx`) from the billed usage.

- `think` values: qwen `true` (boolean only), gpt-oss `'high'` (levels; Ollama ignores `false`), exaone `false` (no thinking mode).

Saved runs (the only Ollama runs among them are `run-01-ko` and `run-01-en`, qwen; the four cloud runs have `retried: {}` and no model failure; `run-02-ko`, gpt-oss, was still running with 29 calls and no failed call):

Call 028 `proofread`: `error.message` is `MAX_TOKENS_MESSAGE`, 1,217,814 ms, cap 32000, `usage` null (that code did not yet attach billed usage). export type RetryReason = 'max-tokens' | 'format'

  helperThink?: HelperThink; hasRetryClient: boolean; productLimits: boolean
}): RetryBudget | null

// eval/novel/eval-client.ts
export interface EvalClientOptions { /* existing */ retryInner?: AiClient }

## Gating

- Local-only, in three layers. (a) Hints are created only when `this.profile.queue === 'local'` (`retryHintOf`), and `planRetry` returns null for any other queue. (b) The think change needs `retryInner`, which `createRetryClient` builds only for `provider === 'ollama'`; `openRun` builds it only when no test `inner` is given. (c) `--product-limits` runs (M4) are never changed, so they still measure the product caps.
- The cloud default path stays exactly as the spec says: Haiku and Luna calls reach the inner client with the same `effort`, `maxTokens`, `model`, system and prompt as before and their call records gain no key (test "cloud and fake profiles never change"). `withModelRetry` calls two new `EvalClient` methods, which do nothing on a cloud profile (`takenRetry` is always null there).
- Nothing under `src/` changes, so product behaviour cannot change. `src/ai/ollama.ts` is read-only because `thinkByTask` already exists.
- No flag, no config key, no summary field: a run created before this change resumes with the new retry behaviour from its next retry on, and old `calls/*.json` and summaries parse as before (`retryBudget` is optional).

## Risks

- A widened call can reach the local call limit: 48,000 tokens at the slowest saved speed (13.6 tokens/s) is 3,529 s against 3,600 s. A timeout is a `model` failure, so the second failure ends the call as `failed` and the run goes on, as with any failed retry. Accepted.
- Lower think may make the retried answer less careful. Only calls that already failed once are affected, and `retryBudget` plus `thinkRequested` mark them. A reviewer or summary writer should not compare a retried call's quality with a first-try call without that mark.
- A cut-off may be a context-window stop, not the output cap (exaone `numCtx` 32768). The `contextOverflow` guard skips widening then, and the ceiling is half of `numCtx`.
- A queued retry call that is aborted while waiting for the local lane still goes through `prepare`, so its failed record may carry a `retryBudget` for a request that was never sent. Harmless; not special-cased.
- The retry client is a second `OllamaAiClient` for the same model and server. `keep_alive` is the same, so Ollama keeps one loaded model, and the lane still serializes calls, so only one request is ever in flight.
- Comparability: first attempts are identical to earlier local runs; only repeated calls differ. A local run before and after this change should compare `state.retried` counts, not retry timings.
- Merge conflicts: M1, M2 and M4 edit `prepare`, `settle`, `Prepared` and `CallRecord` in `eval-client.ts`; M2 and M4 edit `createModelClient`/`openRun` wiring; M1, M2 and M5 edit `blind.ts` and the README. Add lines, never replace theirs. Re-read each region before editing.

## Open questions (default chosen)
