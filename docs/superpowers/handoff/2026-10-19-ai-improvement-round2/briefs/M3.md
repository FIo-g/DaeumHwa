## Goal

Three harness changes so that R2a and R2b reviews are comparable and the pass-line calls are not one reviewer's guess:

1. **Fix the T2 counting scope.** T2 counts only contradictions with facts stated in the bible or the approved wiki. Violations of the style card's writing rules go to Q6 to Q8 (scored, and listed apart). Reviewers, the criteria file and the summary agent all say the same thing.
2. **Second independent reviewer near the line.** After the first review is written, a code gate reads the first review's verdict data. If the run is near the line (Q mean 3.65 to 3.85 inclusive, or exactly one failed threshold T), a second Sonnet reviewer scores the same run from its own blinded copy and writes `review-2.md`. The summary shows both verdicts and marks `판정 불일치` when they differ.
3. **Repeat-run rule in the README.** Rules only; no repeat runs this round (spec section 2, "제외").

## Design (in this order, TDD per step)

### 1. `eval/novel/review-verdict.ts` (pure; write the test file first)

Imports: `zod`, `node:fs` (`existsSync`, `readFileSync`), `node:path`. No other eval imports (blind.ts imports from here, so no cycle).

Constants: `REVIEW_VERDICT_SCHEMA_ID = 'review-verdict-1'`, `SECOND_REVIEW_Q_MIN = 3.65`, `SECOND_REVIEW_Q_MAX = 3.85`, `SECOND_REVIEW_T_FAILS = 1`, `SECOND_REVIEW_FILE = 'review-2.md'`.

zod schema (zod 4.6.7, `z.enum`, `z.literal`, `.refine`):
- chapter: `{ chapter: int >= 1, thresholdsFailed: z.array(z.enum(['T1'..'T7'])), qScores: z.array(z.number().min(1).max(5)).length(9), verdict: z.enum(['publishable','excellent','not-publishable']) }`
- review: `{ schema: z.literal('review-verdict-1'), chapters: z.array(chapter).min(1) }` with a `.refine` that chapter numbers are unique.

`parseReviewVerdict(text)`:
- Collect fenced blocks with `/```json[ \t]*\r?\n([\s\S]*?)\r?\n[ \t]*```/g` via `matchAll`; keep the LAST block whose body includes the schema id string (other json fences in the review are ignored).
- None: `{ ok: false, code: 'no-verdict-block', detail }`.
- Found but `JSON.parse` throws, or `safeParse` fails: `{ ok: false, code: 'invalid-verdict-block', detail }` (detail = parse message, or `issues.map(i => path + ': ' + message).join('; ')`).
- Else `{ ok: true, verdict }`. An invalid last block wins over an earlier valid one (the last block is the reviewer's final word).

`runQMean(v)`: mean of the per-chapter means (each chapter mean = sum(qScores) / 9), then the mean of those, rounded to 2 decimals with `Math.round(x * 100) / 100`. `qMeanNearLine(q)`: `q >= 3.65 && q <= 3.85` on the rounded value (inclusive both ends).

`checkSecondReview(parsed)`:
- `tFailCount` = sum over chapters of the number of distinct ids in `thresholdsFailed`.
- reasons: `'q-mean-near-line'` when `qMeanNearLine(qMean)`; `'single-threshold-failure'` when `tFailCount === SECOND_REVIEW_T_FAILS`. `needed = reasons.length > 0`.
- Parse failure: `needed: true`, `reasons: [code]`, numbers `null` (fail safe: one extra review is cheap, a silently skipped check defeats the point).

`reviewGate(runDir)`: `const review = path.join(runDir, 'review.md')`; throw `Error('review.md missing in ' + runDir)` when absent. `alreadyDone = existsSync(path.join(runDir, SECOND_REVIEW_FILE))`. Result `decision` is `'already-done'` when `alreadyDone`, else `'needed'` / `'not-needed'` from `checkSecondReview`. The result still carries the check fields.

Multi-chapter choice (all R2 runs are 1 chapter): Q mean is the mean of chapter means; the T count is summed over chapters. Say so in a code comment.

## Gating

- M3 is harness and docs only: no `src/` file changes, so the cloud product path and its defaults are untouched. Nothing here depends on `isLocalProvider` or `profile.queue`.
- The second review is on by default for every run (cloud and local) because it is a measurement step, not model behaviour. It is off with `args.secondReview === false`. It runs only after a first review exists.
- The T2 scope and the Q5 narrowing apply to every review written after the criteria file changes (the blind copy reads the file at blind time). Old reviews are not edited.

## Risks

- **A reviewer omits or garbles the block.** The gate fails safe (`needed`), so the cost is one extra reviewer. The guard test pins that the example in `reviewer.md` parses.
- **Block and prose disagree** (for example a Q score typo). The gate trusts the block. The summary agent reads both. A cross-check is not built.
- **Old reviews have no block.** A rerun of the workflow on `2026-10-18` would spawn second reviewers for all of them (fail-safe). README 6.2 says to pass `secondReview: false` there.
- **One failed threshold far from the line also triggers** (qwen en: Q 3.00, only T2 failed). That is the spec's rule; kept.
- **Q5 definition narrowed**, so R2 Q5 is not exactly comparable to round-1 Q5 (a style-card breach used to cost Q5 as well). README 6.1 says so; the R2s versus R2b comparison is unaffected (both R2).
- **Same-family judge.** The second reviewer is the same model family; it measures reviewer noise, not self-bias. Said in criteria section 4 and in the summary caveat.
- **Shared files.** `cli.ts`, `blind.ts` and the workflow are also edited by M1, M2, M4, M5, M6 in the same worktree, in order. M3 edits other lines (new switch cases, new helper functions, the `done` branch, the review functions). Merge theirs, keep both.
- **The behaviour test evaluates the workflow file as a function body.** A top-level `import` or other module-only syntax added later breaks it. M6 (`args.repo`) must keep the file evaluable.
- Stale `blind-2/` copies are rebuilt from scratch each time (`writeBlindCopy` removes the old one), so a second reviewer interrupted before copy is simply redone.

## Open questions (default chosen)

1. Multi-chapter runs: Q mean is the mean of chapter means; failed thresholds are summed over chapters. All R2 runs have 1 chapter, so this is not exercised. Default as stated.
2. Missing or invalid verdict block: treat as near the line (second review runs). Alternative was to skip with a warning; rejected because it silently defeats the check.
3. `rereview: true` does not redo `review-2.md`. To redo it, delete the file. Default as stated.
4. Second reviews go to `docs/eval/novel/<date>/second/<model>-<lang>.md`, not next to the first, so the summary agent's "named `<model>-<lang>.md`" glob in the date folder stays exact.
5. The second reviewer is not told it is second and gets the same prompt text; independence comes from its own blinded copy and the "never open another review" rule.
6. Speech contradictions (character voice fact in bible or wiki) stay in T2, tagged `Characterization (voice)` so R2s can count them. The style card's `tone` (voice) stays in Q5; its `rules` go to Q6 to Q8.
7. The repeat-run thresholds in README 6.3 (0.2 and 1) are design judgment, not measured noise: 0.2 is the width of the 3.65 to 3.85 band. The spec only says "rules".
8. Test file suffix `.m3.r2.test.ts` instead of the plain `.r2.test.ts`: collision avoidance in the shared worktree (see Files).
